## 6. 새 창이 지킬 것

- **`git pull` 을 먼저 한다.** PC 두 대를 GitHub 사이에 두고 번갈아 쓴다.
- **python 은 `.venv\Scripts\python.exe` 로 부른다.** pytest 도 마찬가지다.
- **파일을 열 때 `encoding=` 을 반드시 적는다.** Windows 기본이 cp949 다.
- **파일 수정은 편집 도구로 한다.** heredoc · `echo` · `printf` ·
  `sed`/`awk` 치환 **전부 금지** — 한글·`\`·백틱·`$` 가 **오류 없이 조용히**
  뭉개진다. 스크래치 파일도 같다(`tools\scan_ctrl.py` 의 대상 밖이라 **안 걸릴
  뿐**이다).
- **`PROCEED.md` 「현재 상태」 를 통째로 읽지 마라** — 미해결 칸이 한 줄에
  2만 2천 자다. `tools\daily_brief.py` 의 `open_items` 로 이름을 떠 온다.
- **수는 두 방법으로 재서 같은지 본다.** S152 에서 어긋난 자리 셋 —
  덱 벌을 `key=` 로 세면 18 이 나온다(`key="` 로 좁히면 17) · 브리핑이 찍는
  「칸 N자」 는 「다음 작업」 이 아니라 **미해결 칸**이다 · 미해결 ② 는
  **머리말과 줄 수가 같아야 한다**(① 은 한 줄이 넷을 담아 다르다).
- **종료 코드만 보고 통과를 판정하지 마라.** 수집 건수와 skip 수를 함께 본다.
- **세션을 마칠 때 미해결 대조를 이름으로 적는다** — 수만 맞추면 하나 늘고
  하나 준 판이 안 보인다. **세션 목록표 행에 적는다**(못이 그 행을 문다).
- **그 못은 마감 회귀 뒤에 다시 돌려야 값이 된다** — S152 0-2 가 값으로
  짚었다. 마감 pytest 는 **앞 판의 행**을 본다.
- **커밋 뒤 `git push` 한다.** 올리지 않으면 그 PC 에만 남는다.

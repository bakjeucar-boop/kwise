# 문구 판 목록 — 사용자가 Streamlit 을 열고 볼 자리

**S157(준비 판)이 만들었다. 이 판은 문구를 한 글자도 안 고쳤다.**
다음 판(S158)이 사람과 함께 화면을 열어 **무엇을 어떻게 고칠지 정한다.**

**여기에 고칠 안을 쓰지 않는다.** 담는 것은 「무엇이 어디에 어떻게 적혀
있나」 까지다. 문안을 지어 두면 화면을 보기 전에 결론이 서고, 그러면
화면을 여는 일 자체가 확인 절차로 줄어든다.

---

## 잣대 — 고치기 전에 이것부터 읽는다

`CLAUDE.md` 「화면 문구」 절이 정본이다. 세 줄로 줄이면 이렇다.

1. **화면 문구는 늘리지 않는다.** 새 안내를 붙이기 전에 **용어나 이름을
   고쳐서 해결되는지** 먼저 본다 — 설명이 필요하다는 것은 대개 이름이
   틀렸다는 뜻이다.
2. **문구를 하나 더할 때는 무엇을 뺄지 함께 정한다.** 예산은
   **본문 3줄 · 확인사항 3항목**이고 장치는 `tools\screen_budget.py` 다.
   배경·근거·제도 설명은 `docs\MANUAL.md` 로 보낸다.
3. **고치기 전과 후에 `tools\screen_audit.py` 를 돌린다.** 수가 늘었으면
   늘린 이유를 적는다.

**캡처는 `docs\CAPTURES.md` 의 「S157 판」 절에 있다** —
`%LOCALAPPDATA%\kwise\cache\screens\`. 저장소 밖이라 다른 PC 에서는
`tools\capture_screen.py` 로 다시 뽑는다.

## 4. 닫힌 것 — 다시 열지 마라

- **97% 정확히에서 두 삼각형이 겹치는 자리는 없다.** S156 이 이미 닫았다 —
  `has_no_headroom` 이 `current_pct >= cap and target_pct >= cap` 이라
  **97 은 97 이상이다.** S157 이 `역률-97_*.png` 로 값을 봤다: 「개선 여지
  없음」 · 삼각형 하나 · 범례 「현재」 뿐. S157 지시서가 「남았다」 고 적은
  것은 S156 의 **고치기 전 서술**을 남은 결함으로 읽은 것이다.
- **12개월 미만 경고는 「데이터 품질」 에 없다.** 그 위 안내 블록이 낸다
  (`views\diagnose.py::_quality_block` 첫 줄). 캡처 자리를 찾을 때 헤매지
  않도록 적어 둔다.

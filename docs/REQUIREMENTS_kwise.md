# kWise 요구사항서

건물 전력 비용 진단 및 개선안 비교
문서 버전 1.0 · 2026-08-06

---

## 1. 개요

### 1.1 목적

**운영 중 건물의 15분 실측 전력 데이터로 전력 비용 구조를 진단하고,
요금제 전환·계약 조정·태양광·ESS 등 개선 수단의 효과를 같은 기준으로 비교한다.**

태양광은 여러 개선 수단 중 하나다. 설비 투자 없이 요금제와 계약만 조정해도
상당한 절감이 나오는 경우가 많으며, 그 판정이 이 도구의 첫 산출물이다.

### 1.2 세 계층

| 계층 | 질문 | 산출 |
|---|---|---|
| **진단** | 지금 어떻게 쓰고 얼마 내고 있나 | 부하 패턴, 요금 구조, 계약 적정성, 피크 특성 |
| **개선** | 무엇을 하면 얼마가 줄어드나 | 수단별 절감액·투자비·회수기간 |
| **비교** | 어느 조합이 최선인가 | 같은 기준의 나란한 비교, 확실성 등급 |

### 1.3 이 도구가 푸는 문제

손계산으로 답할 수 없는 것에 집중한다.

| 문제 | 왜 손계산이 불가능한가 |
|---|---|
| 최적 선택요금 판정 | 시간대별 사용량 분포가 필요하고, 설비 도입 후 그 분포가 바뀜 |
| 계약전력 적정성 | 15분 최대수요 이력 전체가 필요 |
| 기본요금 절감 가능 여부 | 연중 어느 15분이 최대인지, 그 순간 발전량이 얼마인지 시계열 없이 알 수 없음 |
| ESS 최소 용량 | 목표 피크를 지키는 출력·용량은 디스패치 시뮬레이션이 필요 |
| 잉여 발생량과 시간대 분포 | 시계열 필요 |

연간 발전량, 자가소비율, 전력량요금 절감의 개략치는 엑셀로도 나온다.
**이 도구의 존재 이유는 위 다섯 가지다.**

### 1.4 대상 사용자와 적용 국가

사내 설계·영업 담당자. 발주처 제안 및 초기 검토 단계에서 근거 있는 답변을 만드는 것이 목적이다.

**kWise 는 대한민국 전용 도구다.** 산출물 전체가 한국의 제도에 의존한다.

| 요소 | 근거 | 다른 나라에서 성립하지 않는 이유 |
|---|---|---|
| 요금 체계 | 한전 **기본공급약관**·전기요금표 | 계약종별·선택요금Ⅰ/Ⅱ/Ⅲ·계절·시간대 구분이 한전 고유다 |
| 기본요금 | 약관 제68조 — **요금적용전력** (직전 12개월 최대) | 이 산정 방식 자체가 한전 제도다 |
| 역률요금 | 약관 **제41~43조** — 92% 기준, 매 1%당 0.2% | 기준값도 조정률도 약관이 정한다 |
| 공휴일 | 관공서 공휴일 규정 + 일요일 | 요금 시간대 판정이 국가 달력에 묶인다 |
| 경제성DR | **전력시장운영규칙 제12장** | 전력거래소 시장 규칙이다 |
| 지역 선택 | 시군구 좌표 **229개** (`data\sigungu_kr.json`) | 좌표 데이터가 있는 지역만 고를 수 있다 |
| 기상 사전 취득 | 국내 135개 격자 (7.5) | 사전 취득 범위가 한반도로 한정된다 |

계산 로직 일부(PV 시뮬레이션, ESS 디스패치, 부하 통계)는 국가 중립적이지만
**요금이 붙지 않으면 결론이 나오지 않는다.** 해외 적용은 범위 밖이다.

**지역 데이터팩 같은 다국가 추상화를 만들지 않는다.** 쓰지 않을 구조는 복잡도만
늘린다. 다른 나라를 지원해야 할 일이 실제로 생기면 그때 설계한다.

### 1.5 범위 밖

- **대한민국 외 국가** — 요금 체계·역률 규정·공휴일·DR 규칙·지역 좌표가 모두
  한국 제도에 묶여 있다 (1.4). 요금표만 바꿔 끼우는 식으로는 동작하지 않는다
- **신축 건물 부하 예측** — 실측 데이터가 없는 건물. 별도 프로젝트로 계획
- 건물 에너지 시뮬레이션 — 실측 부하를 쓰므로 불필요
- ZEB·건축물에너지효율등급 등 **인증용 산출**
- 기후환경요금, 연료비조정요금, 부가가치세, 전력산업기반기금
- 역률요금 (추정 역률 기반. 추가·감액을 모두 금액으로 낸다 — 5.7)
- 계통연계 기술 검토, 보호협조
- 상계거래·외부 신재생에너지 구매의 **자격요건 판정** (금액만 참고 제시)
- **신뢰성DR (의무감축)** — 용량요금 정산과 의무 이행 판정이 따른다. 경제성DR만 다룬다
- **플러스DR (자발적 수요증대)** — 전력시장운영규칙 **제12.7.3.1조 제3호**에 따라
  표준DR·중소형DR·제주DR·국민DR·주파수DR은 자발적 수요증대 거래에 참여할 수 없다.
  별도 등록된 플러스DR 자원만 가능하며 정산단가도 제주 기준이다
- **CBL(고객기준부하) 산정** — **제12.5.2.1조**에 따라 전력거래소가 별표28 방식으로
  산정한다. 우리가 만들지 않는다
- **DR 참여 자격 판정** — 수요관리사업자와 전력거래소의 등록 절차다
- **태양광 설비 설계와 배치 검토** — kWise 는 **도입 전 검토 도구**다. 모듈 배치,
  스트링 구성, 음영 시뮬레이션, 구조 검토는 별도 도구(pvsim)의 몫이다.
  방위·경사·GCR·손실률을 받기는 하지만 **밀도 프리셋의 기본값을 미세 조정하는
  용도**이며, 상세 설계 모드를 두지 않는다 (3.3)

## 2. 실행 환경

상세는 `docs/ENVIRONMENT.md` (Windows 11) 를 따른다. 핵심만 옮긴다.

| 제약 | 대응 |
|---|---|
| Windows 기본 인코딩이 cp949 | `PYTHONUTF8=1` 등록, 파일 열 때 `encoding=` 명시 |
| pvlib은 tz-aware 인덱스 생성 | **Excel 출력 직전 `dt.tz_localize(None)`** — 누락 시 `ValueError` |
| Excel 파일 잠금 | 결과 파일명에 날짜·시각 접미사, 저장 실패 시 안내 |
| 한글 폰트 | 맑은 고딕 내장. matplotlib 사용 시 `font.family = "Malgun Gothic"` |
| 경로 | `pathlib.Path` 만 사용. 문자열 결합·구분자 하드코딩 금지 |
| 메모리 | 여유가 있어도 다중 시나리오를 한 번에 올리지 않는다. 순차 처리 |
| 가상환경 | 프로젝트 내 `.venv`, `pip install -e .` |

**배포** — 1단계는 Streamlit 웹 UI(로컬 실행). 발주처 사용량 데이터를 다루므로
로컬·사내망을 기본으로 하고, 업로드 데이터는 서버에 영구 저장하지 않는다.
단독 실행 exe 전환은 향후 별도 검토한다.

### 2.1 패키지 구조

```
src/kwise/
├── io/         사용량 데이터 로더
├── quality/    품질 검사, 정전 검출
├── tariff/     요금 엔진, 시간대 분류
├── pv/         태양광 계산, 기상 취득
├── diagnose/   진단 — 부하 패턴, 피크 특성, 계약 적정성
├── measures/   개선 수단 평가 — 요금제, 계약, PV, ESS, 잉여
├── compare/    조합 비교
├── report/     Excel 출력, CLI 배치
└── ui/         Streamlit 화면
```

의존 방향은 위에서 아래로만 흐른다. `ui` 는 계산 로직을 담지 않고 순수 함수를 호출만 한다.

## 3. 입력 사양

### 3.1 사용량 데이터 (필수)

한전 사이버지점에서 내려받는 CSV 형식을 기본으로 한다.

```
검침일,순방향 유효전력량(KWH)
2023-04-25 00:15,321.84
```

| 항목 | 요구 |
|---|---|
| 인코딩 | utf-8-sig, cp949, euc-kr, utf-8 순차 시도. 컬럼 매칭 성공까지 확인해야 채택 |
| `24:00` 표기 | 다음 날 `00:00` 으로 변환 |
| 파일 형식 | csv, xls, xlsx |
| 시간 간격 | 15분·1시간 자동 인식. 1시간 데이터는 기본요금 판정에 한계가 있음을 경고 |
| 컬럼명 | 후보 목록 기반 유연 매칭 |
| 기간 | 역년이 아닌 임의 기간 허용 |
| 그리드 위상 | 최빈값으로 판정 |
| **라벨 규약** | **검침일 라벨은 구간 끝이다.** 하루가 `00:15` 로 시작해 `24:00` 으로 끝나 96행이 된다. 계절·시간대·월 귀속은 라벨에서 한 구간을 뺀 시각으로 판정한다. `15:00` 슬롯은 `14:45~15:00` 사용량이므로 중간부하이며, 첫 최대부하 슬롯은 `15:15` 이다. **PV 시계열을 붙일 때 같은 규약을 적용해야 15분 어긋나지 않는다.** |

### 3.2 계약 정보 (필수)

**진단 단계에서 필요한 유일한 입력이다.** 설비 정보는 이 단계에서 묻지 않는다.

| 항목 | 입력 방식 | 비고 |
|---|---|---|
| 계약종별 | 사용자 직접 선택 | 데이터로 추정 불가 |
| 계약전력 (kW) | 사용자 입력 | 청구서 기재값. 적정성 진단의 전제 |
| 전압구분 | 선택 | 계약전력으로 후보 제시 |
| 선택요금 | 선택 | 추정치 제시, 어차피 전 조합 계산 |
| 주간 지상역률 (%) | 입력, 기본값 92 | 약관 제42조의 무효전력계 미설치 간주값. 이 값에서 추가·감액이 0 |
| 야간 진상역률 (%) | 입력, 기본값 없음 | 모르면 산출하지 않고 경고만 낸다 (제43조 ②) |

**추정 보조** — 업로드 직후 아래를 계산해 제시하고 사용자가 확정한다.

- 갑/을 구분 — 계약전력 임계값 (일반용·산업용 300 kW, 교육용 1,000 kW)
- 전압구분 후보 — 계약전력 규모 기반
- 연간 이용시간 = 연간 사용량 ÷ 최대수요 → 선택요금 후보
- 계약종별 힌트 — 부하율·주말 부하 비율·계절 패턴으로 성격 추정 (확정 아님)

### 3.3 개선 수단별 입력

**2단계에서 해당 수단을 켤 때만 묻는다.** 진단만 볼 사용자는 아무것도 입력하지 않는다.

**태양광 — 기본 입력은 3개다**

요금 절감 검토 단계에서 사용자가 아는 것은 유휴 면적 정도다. 방위·경사·손실률을
정밀하게 받아도 **발전량 예측 R² 가 0.8** 이라 기상 데이터가 지배하는 오차 앞에서
입력 정밀도는 효과가 없다. 게다가 **PV 용량 곡선이 이미 용량을 20단계로 훑으므로,
면적→용량 환산이 ±20% 틀려도 곡선 위의 다른 점을 보는 것일 뿐 결론이 바뀌지 않는다.**

| 기본 입력 | 기본값 |
|---|---|
| 설치 가능 면적 (m²) | — |
| 설치 밀도 | 보통 |
| 지역 | 시군구 선택 (또는 위경도 직접 입력) |

**설치 밀도 프리셋** — 밀도 하나로 GCR 과 경사각을 **함께** 정한다. 고밀도 배치는
이격을 좁히는 대신 경사를 낮춰 음영을 줄이는 것이 실무 관행이다.

라벨은 **"설치 밀도"**, 값은 **높음 / 보통 / 낮음**이다. 내부 키는
`high` / `normal` / `low` 이며 **표시 라벨과 분리한다** — 산출물에 구어체를
쓰지 않기 위해서다.

| 설치 밀도 | GCR | 경사각 | 1,000 m² 환산 | 상충 관계 |
|---|---|---|---|---|
| 높음 | 0.55 | 15° | 110 kWp | 면적당 용량 최대. 대신 이격이 좁아 kWp당 발전량은 최소 |
| **보통** | **0.40** | **25°** | **80 kWp** | 면적당 용량과 kWp당 발전량의 균형점 (기본값) |
| 낮음 | 0.30 | 30° | 60 kWp | kWp당 발전량 최대. 대신 같은 면적의 용량은 최소 |

**각 선택지에 상충 관계를 한 줄로 병기한다.** 밀도만으로는 "높으면 좋은 것인지"를
알 수 없기 때문이다. 그리고 **선택 즉시 환산 용량을 함께 보여 준다** —
1,000 m² 라면 110 / 80 / 60 kWp 다.

    설치 용량(kWp) ≈ 설치 가능 면적 × GCR ÷ 5

모듈 효율 20% 기준 1 kWp 당 약 5 m² 다. 환산 결과를 화면에 표시한다.
방위각은 남향(180°)이 기본이다.
**프리셋은 `data/pv_presets.json` 에 둔다. 하드코딩 금지.**

| 확장 패널 (접어 둔다) | 기본값 |
|---|---|
| 설치 용량 (kWp) 직접 입력 | — (주면 면적 환산을 덮어쓴다) |
| 방위각 / 경사각 | 180° / 밀도 프리셋 값 |
| GCR 직접 지정 | 밀도 프리셋 값 |
| 시스템 손실 | 14% |
| 벽면 PV 적용 | 선택 (경사각 90°) |
| 다중 어레이 | 선택 |
| 위경도 직접 입력 | 시군구 중심점 |

⚠ **모드를 나누지 않는다.** 한 화면에서 접었다 펴는 구조다. 상세 설계 모드를
만들면 pvsim 과 경계가 흐려진다 (1.5 절).

**지역 선택**

Open-Meteo 가 쓰는 ERA5 격자는 25~31 km 다. 시군구 중심점과 실제 부지의 거리가
격자보다 작으면 **같은 셀을 조회**하므로 결과가 같다. 서울 25개 구의 좌표 폭이
남북 20.6 km · 동서 29.0 km 이므로 서울 안에서는 구를 바꿔도 같은 격자가 나올 수
있다. **시군구 단위 선택은 정확도를 희생하지 않는다.**

- 기본: 시도 → 시군구 2단 (`data/sigungu_kr.json`, 229개). **드롭다운은 이 데이터에서 생성한다.**
- 옵션: 위경도 직접 입력 — 산악·해안 지형이나 넓은 시군구용
- 기상 캐시 키는 **0.25° 격자로 반올림**한다. 시군구 선택이든 좌표 직접 입력이든
  같은 격자면 캐시를 공유한다.

## 4. 데이터 품질 검사

업로드 직후 요약을 표시한다. **조용히 넘어가지 않는다.**

### 4.1 점검 항목

| 항목 | 판정 | 표시 |
|---|---|---|
| 기간 | 시작·종료·총 일수 | 12개월 미만이면 경고 |
| 결측 | 예상 행수 대비 누락 수·비율 | 3% 초과 시 경고 |
| 결측의 시간대 분포 | 피크 시간대(10~16시, 평일) 편중 여부 | 편중 시 **"최대수요 과소평가 위험"** |
| **최장 연속 결측 구간** | 가장 긴 연속 공백의 길이와 기간 | 1일 초과 시 경고 |
| **월별 결측률** | 월마다 개별 산출 | 5% 초과 월은 별도 표시 |
| **정전 구간** | 연속 결측 + 직전 부분 적산 행 + 복전 후 저부하 | 구간과 지속시간 |
| 이상치 | 0 kW, 계약전력 초과, 급변 | 건수 |
| 중복 시각 / 간격 일관성 | | 처리 방침 표시 |

**연속 공백은 편중과 다른 위험이다.** 편중 배수는 결측이 특정 시간대에 몰렸는지만 본다.
며칠짜리 연속 공백은 모든 시간대가 균등하게 빠지므로 배수가 1 근처가 되어 음성으로
판정되지만, 실제로는 그 달의 최대수요 판정 자체를 무의미하게 만든다.
편중 배수와 최장 연속 결측을 **모두** 산출한다.

**정전 구간은 결측과 구분한다.** 정전 중에는 피크가 발생할 수 없으므로 편중 판정에서
제외해야 정확하다. 계량기 통신 장애로 인한 결측은 실제 피크를 놓쳤을 수 있지만 정전은 아니다.
정전 판정은 **흔적 3종 중 연속 결측을 뺀 나머지 2개 이상**을 요구한다.
연속 결측은 모든 결측이 갖는 성질이라 근거가 되지 못한다.

편중 판정에서 정전 슬롯은 **분자·분모 양쪽에서** 뺀다. 한쪽만 빼면 비율이 왜곡된다.
제외한 값이 정본이고, 포함한 값은 비교용으로 함께 담는다.

### 4.2 결측 처리

- 기본: **보간하지 않는다.** 결측 구간은 계산에서 제외하고 그 사실을 명시한다.
- 최대수요는 관측된 값 중 최대이며, 결측 구간에 더 큰 값이 있었을 수 있음을 표기한다.
- 결측률 5% 초과 월은 요금 명세에 결측률을 병기하고 최대수요를 **"신뢰 제한"** 으로 표시한다.
- 선형보간 옵션을 두되 기본값은 미적용.

### 4.3 그리드 이탈 행

15분 그리드를 벗어난 행(부분 적산)은 아래처럼 처리한다.

| 용도 | 처리 | 이유 |
|---|---|---|
| kW 수요 산정 | **제외** | 위상이 달라 15분 평균 환산 시 수요가 왜곡됨 |
| kWh 사용량 합계 | **포함** | 실제 사용된 전력량. 한전 청구도 적산값 기준 |
| 결측 판정 | 별도 분류 | "결측"이 아니라 "부분 계량" |

## 5. 요금 엔진

### 5.1 계산 대상

**기본요금과 전력량요금만 계산한다.** 그 외 요금요소는 산출물에 미포함으로 안내한다.

> 본 결과는 기본요금과 전력량요금만 산출한 값입니다. 기후환경요금, 연료비조정요금,
> 부가가치세, 전력산업기반기금은 포함되지 않았습니다. 이들은 모두 사용전력량에
> 비례하므로 실제 절감액은 본 결과보다 다소 크게 나타납니다.

### 5.2 기본요금

```
기본요금(월) = 요금적용전력 × 종별·전압·선택요금별 기본요금 단가
```

**요금적용전력 규칙 (한전 기본공급약관 제68조)**

세 조건이 겹친다. 하나라도 빠뜨리면 결과가 크게 어긋난다.

**① 대상 시간대 — 경부하 제외**

일반용(을), 산업용(을), 교육용(을), 일반용(갑)Ⅱ, 산업용(갑)Ⅱ 는
**중간부하와 최대부하 시간대의 최대수요전력 중 큰 것**만 대상이다.
경부하 시간대(22:00~08:00)의 수요는 아무리 커도 요금적용전력이 되지 않는다.

공휴일은 최대수요전력을 경부하로 계량하므로 **공휴일 피크도 자동으로 제외**된다.

**② 대상 월 — 하계·동계 + 당월**

```
요금적용전력 = max( 7·8·9월, 12·1·2월, 검침 당월 )   ← 직전 12개월 범위 내
```

3~6월과 10~11월의 피크는 그 달의 당월분으로만 잡히고 이후 달로 이월되지 않는다.

> **주의 — "하계·동계"와 전력량요금의 "계절"은 다르다.**
>
> | | 대상 |
> |---|---|
> | 요금적용전력 대상월 | 7·8·9 · 12·1·2 |
> | 전력량요금 계절 | 여름 6·7·8 / 봄가을 3·4·5·**9**·10 / 겨울 **11**·12·1·2 |
>
> 9월은 전력량요금상 봄·가을철이지만 요금적용전력 대상월이다.
> 6월과 11월은 반대로 여름·겨울 단가를 쓰지만 대상월이 아니다.
> **같은 함수로 판정하지 말 것.**

**③ 하한 — 계약전력의 30%**

위 ①②로 구한 값이 계약전력의 30% 미만이면 계약전력의 30%를 적용한다.
**종별로 갈리지 않는다** (90세션) — 15% 는 세칙 별표4 8.「초·중·고교 및 유치원
전기요금 적용」 의 **신청** 특례이지 종별 속성이 아니다. 자리는 종별 속성으로
두되(`contract_floor_ratio`, 기본값 0.30) 값은 여덟 종별이 같다.

**기본요금 기준 — 갈림길은 갑/을이 아니라 공급전압이다**

약관 제68조 제1항은 **최대수요전력계가 설치된 고객**의 기본요금을 요금적용전력
으로 매기고, 제2항은 나머지를 계약전력으로 매긴다. 그 설치를 정하는 것이
제38조 제2항이다 — 「고압 이상의 전압으로 전기를 공급받는 고객에게는
최대수요전력과 무효전력을 계량할 수 있는 전력량계를 설치합니다」.
본 도구는 이를 `base_fee_basis` 로 관리한다 (`"billing_demand"` / `"contract"`).

    저압이 없는 종별 (을 · 갑Ⅱ)   언제나 고압 → 요금적용전력
    교육용(갑) 고압A·B            제38조 ②로 계량기가 선다 → 요금적용전력
    교육용(갑) 저압 · 갑Ⅰ         계량기가 없는 것이 기본값 → 계약전력

**기준은 종별 속성이 기본값이고 전압이 그것을 덮는다.** 갑Ⅰ 고압 행은
제57조 제4항·제59조 제5항이 갑 고압을 갑Ⅱ 로 보내므로 **저압계량 예외
경로**이고, 그래서 전압별 예외를 두지 않는다. 교육용에는 갑Ⅱ 가 없어 그
단서가 서지 않는다.

계약전력으로 매긴 자리에는 **계량기가 실제로 섰는지 확인하라는 경고**를 실어
화면·산출물로 내보낸다. 계약전력을 주지 않으면 금액을 만들어내지 않고 멈춘다.

**그 밖에**

- 최대수요전력 = 15분 평균 수요의 최대값
- 직전 이력이 없으면 첫 몇 달이 과소 산출된다. `prior_peaks=` 인자로 주입 가능하게 하고,
  주입되지 않으면 경고를 붙인다.
- 계약전력을 초과하면 초과사용부가금이 부과된다. 경부하 시간대 초과는 요금적용전력에
  영향을 주지 않지만 초과사용부가금 대상은 되므로 별도로 검사한다.

**이 규칙들이 결과에 미치는 영향**

- **봄·가을 피크 저감은 기본요금 절감 가치가 거의 없다.** 그런데 태양광 발전이
  가장 강한 계절이 봄·가을이다. PV 의 기본요금 기여는 7~9월에 집중되고
  12~2월에는 발전이 약하다. 이 비대칭을 산출물에 명시한다.
- **ESS 야간 충전이 만드는 피크는 기본요금 대상이 아니다.** 다만 계약전력 초과
  여부는 검사해야 한다.

### 5.4 결측이 있는 월의 처리

전력량요금은 사용량에 비례하므로 결측이 있는 월은 과소 계산된다.
기본요금은 최대값 기반이라 보정할 수 없다.

| 기준 | 방법 | 용도 |
|---|---|---|
| 관측 기준 | 있는 데이터 그대로 | 기본 표시값. 보수적 |
| 결측 보정 기준 | 월별 전력량요금을 `1 ÷ (1 − 결측률)` 로 환산 | 회수기간 산정 참고 |

어느 쪽을 썼는지 산출물에 반드시 표기한다. 도입 전후 차분(Δ)에는 같은 결측이
양쪽에 걸리므로 왜곡이 상대적으로 작다. **절대 금액보다 Δ 를 우선 신뢰한다.**

### 5.5 부분 월과 기간 표기

실무 데이터는 검침일 기준이라 역년이 아니다. 샘플은 2023-04-25 ~ 2024-04-27 로
월 버킷이 13개이며 앞뒤 두 개가 부분 월이다.

- **부분 월의 기본요금을 온전히 부과하지 않는다.** 두 조각을 합쳐 한 달로 처리하거나
  일수 비례로 안분한다. 어느 쪽을 썼는지 산출물에 표기한다.
- **결과를 "연간"으로 표시하지 않는다.** 실제 기간을 명시하거나 12개월로 환산한다.
- 12개월 미만 데이터는 환산 시 경고를 붙인다.

**구현 방침**

1. **추가와 감액을 모두 금액으로 계산한다.** 기본요금의 −1.0% ~ +6.4% 라
   경고로만 둘 수 없다. 기본요금이 연 4.5억 원인 사례에서 1%가 450만 원이다.
2. **야간 진상역률 95% 조항도 넣는다.** ESS 야간 충전과 PV 인버터의 진상
   무효전력이 여기 걸린다. 진상역률을 모르면 산출하지 않고 경고만 낸다 —
   무효전력 실측 없이 지어낼 근거가 없다.
3. **PV 도입 후 예상 역률을 계산한다.** 무효전력은 그대로인데 PV가 유효전력만
   상쇄하므로 역률이 떨어진다. 판정 창은 약관과 같은 **08~22시**(구간 시작 기준)다.
   92% 미만이면 콘덴서 조정 필요와 **예상 추가요금**을 함께 제시하고,
   그만큼 깎인 절감액을 병기한다.
4. **역률 개선을 개선 수단으로 둔다** (7.4). 투자비가 작아 회수기간이 짧다.
5. **추정 역률의 기본값은 92%다.** 지어낸 값이 아니라 제42조가 무효전력계
   미설치 고객에게 적용하는 **간주값**이다. 이 값에서 추가·감액이 정확히 0이
   되므로, 역률을 모르는 채로 금액을 만들어내지 않는다.
6. **제43조 ③(첫 달 예고)은 계산에 넣지 않는다.** 첫 달을 빼면 기간에 따라
   금액이 달라져 도입 전후 비교(Δ)가 흔들린다. 주석으로만 남기고, 실제 첫 달
   청구서와 어긋날 수 있음을 산출물에 적는다.

**한계.** 본 도구의 데이터는 15분 유효전력뿐이라 제42조의 30분 누적 계량을
재현할 수 없다. 추정 역률 기반이라는 사실을 부록 D에 적는다.

## 6. 진단

**설비 정보 없이, 업로드와 계약 정보만으로 나오는 결과다.**

### 6.1 부하 패턴

| 지표 | 의미 |
|---|---|
| 부하율 | 평균 ÷ 최대 |
| 기저부하 비율 | 야간 평균 ÷ 주간 평균 |
| 주말 부하 비율 | 주말 평균 ÷ 평일 평균 |
| 운영시간 외 부하 | 운영시간 외 사용량 |

기저부하가 과다하면 상시 가동 설비 점검 여지를 시사한다.

### 6.2 피크 특성

**단일 최대값이 아니라 월별 최대수요 12개를 산출한다.** 요금은 월별로 매겨지고,
요금적용전력은 그 이력의 최대치다.

| 산출 항목 |
|---|
| 월별 최대수요, 발생 시각 |
| 요금적용전력 |
| **연간 상위 100개 15분 구간의 시각·요일 분포** |
| 시간대별 평균 부하 프로파일 |

상위 구간의 시각 분포는 **태양광의 피크 기여 가능성을 즉시 보여주는 지표**다.
건물마다 정반대 결과가 나오므로 반드시 표시한다. 오전·정오 집중이면 PV 기여가 크고,
저녁·아침 집중이면 거의 없다.

### 6.3 현재 요금 구조

- 기본요금 대 전력량요금 비중
- 시간대별(경/중간/최대) 사용량 비중
- 계절별 사용량 비중
- 월별 요금 명세

### 6.4 계약전력 적정성

```
최대수요전력 ÷ 계약전력
```

계약전력 대비 최대수요가 낮으면 과계약이다. **PV와 무관하게 즉시 돈이 나오는
항목이다.**

**다만 이득이 있느냐는 이용률이 아니라 하한이 정한다** (83세션). 기본요금이
요금적용전력에 붙는 종별에서는 요금적용전력이 `max(최대수요, 계약전력 ×
하한비율)` 이므로, 하한이 최대수요보다 클 때만 계약전력을 낮춰 요금이 준다.
목표 계약전력은 `최대수요 ÷ 하한비율` 이고, 하한이 지면 목표도 절감액도 없다.

단, 계약전력 하향은 되돌리기 어렵고 초과 시 위약금이 있으므로 **여유 확보 권고를 함께 표시한다.**

### 6.5 개선 여지 요약

```
계약전력 조정    연 ○○○만원      투자 불필요
태양광 검토      피크 기여 가능성 높음 / 보통 / 낮음
```

### 6.6 경제성DR 참여 여력

근거는 `data/source/2024-02_전력시장운영규칙.pdf` 제12장 「수요반응자원의 거래」다.

| | 신뢰성DR | 경제성DR |
|---|---|---|
| 성격 | 수급 비상 시 **의무** 감축 | 하루 전 **자발적** 입찰 |
| 정산 | 용량요금 + 실적금 | 실적금만 |
| 설비 | 필요 | 불필요 |
| 본 도구 | **범위 밖** | **대상** |

**거래일 제약이 이 절의 핵심이다 (제12.4.2.1조 제1항 1호).**

> "관공서의 공휴일에 관한 규정"의 공휴일과 **토요일**을 제외한 평일의 거래일에만
> 입찰할 수 있다.

일요일은 공휴일 규정에 포함되므로 자동으로 빠진다.
**이 제약을 빼면 감축 가능량이 30% 이상 과대평가된다** (샘플 359일 중 245일).

⚠ **요금 계량의 "평일" 정의와 다르다.** 요금 엔진은 토요일을 공휴일로 보지 않고
(최대부하 → 중간부하로 낮출 뿐) 일요일만 공휴일로 계량한다. DR 은 토·일·공휴일이
모두 똑같이 제외다. **별도 함수로 분리한다** (`diagnose.dr.dr_day_mask`).

**제12.4.2.1조 제1항 2호** — 거래시간별 감축가능용량은 0.1 MW-h(100 kW) 이상이어야
한다. 단, **수요관리사업자가 묶은 자원 단위 기준**이므로 개별 고객에게 그대로
적용되지 않는다. 참고 문턱으로만 표시한다.

**자원 유형 판정 (제12.1.1조)** — 이미 입력받는 계약종별·계약전력으로 판정한다.

| 유형 | 요건 |
|---|---|
| 표준DR | 계약종별 제한 없음 |
| 중소형DR | 일반용·주택용·농사용·교육용. **산업용은 2 MW 이하** |
| 국민DR | 계약전력 200 kW 이하, 주택용, 집합건물 개별세대 |

**산출 항목**

> **14세션 개정.** 연간 참여 일수 제한이 없음을 전력거래소에서 확인했다. 남는
> 제약은 하루 2회·총 8시간, 평일 09~20시(점심 제외), 미이행 시 6개월 입찰
> 제한이다. 따라서 **실질 제약은 감축할 여력이 있는 날이 며칠이냐 하나**이며,
> 기저부하 비율과 하위 5% 분위수를 쓰던 아래 3·4항을 주말 기준선 방식으로
> 대체했다.

1. **DR 대상일 수** (월~금, 공휴일 제외). 이후 모든 산출의 분모다.
2. 참여 가능 자원 유형
3. **저부하 평일 식별**
   - 기준선 = **주말·공휴일**의 판정 시간대 평균 부하. 건물이 사실상 비어 있을
     때의 수준이다. 판정 시간대는 **시장 운영 시간대(09~12·13~20시)와 건물 운영
     시간대(옆단 입력, 기본 09~18시)가 겹치는 구간**이다 — 시장이 열려 있어도
     건물이 비어 있으면 줄일 것이 없고, 건물이 돌아도 시장이 닫혀 있으면 입찰할
     수 없다. 둘은 다른 값이며 코드에서도 이름을 가른다
     (`dr.market_hours` / `building.operating_hours`).
   - 저부하 평일 = DR 대상일 중 그 시간대 평균이 기준선의 일정 배수(기본 1.2배)
     이하이고 정전 구간이 아닌 날. 배수는 `assumptions.json` 에 둔다.
   - **목록으로 보여 준다.** 창립기념일·워크숍처럼 사무실을 비우는 날일 가능성이
     높아, 맞는 날인지는 사용자가 판정한다.
4. **감축 가능량**
   - 감축 여력 = 평일 정상 평균 − 그날 실제 부하
   - 참여 시간 = 하루 8시간을 상한으로 하되 저부하가 실제로 지속되는 시간까지
   - 연간 감축 가능량 = Σ(저부하일별 감축 여력 × 그날 참여 가능 시간)
   - **보수적으로 산정한다.** 등록값은 평균이 아니라 저부하일 감축 여력 분포의
     하위값이다 — 평균으로 등록하면 절반의 날에 미달하고, 미달은 6개월 입찰
     제한이다.
5. 적합성 등급 (높음 / 보통 / 낮음)

## 7. 개선 수단 평가

**투자비 순으로 배치한다.** 사용자가 필요한 수단만 켠다.

### 7.1 선택요금 전환 (투자 0)

가능한 모든 선택요금 조합을 계산하여 표로 제시한다.

| 계약종별 | 선택요금 |
|---|---|
| 일반용(갑)Ⅰ, 산업용(갑), 교육용 | Ⅰ, Ⅱ |
| 일반용(을), 산업용(을) | Ⅰ, Ⅱ, Ⅲ |
| 일반용(갑)Ⅱ | Ⅰ, Ⅱ, Ⅲ, Ⅳ |

**두 기준을 모두 보여준다.**

1. 현행 선택요금 유지 기준
2. 최적 선택요금 전환 기준

설비 도입과 무관하게 선택요금 전환만으로 나오는 절감액을 별도 표시한다.
**설비 없이도 가치가 나오는 핵심 기능이다.**

선택지 목록은 요금 데이터 파일에서 생성한다. 하드코딩 금지.

### 7.2 계약전력 조정 (투자 0)

6.4 진단 결과를 근거로 목표 계약전력과 예상 절감액, 위약금 위험을 제시한다.

### 7.3 경제성DR (투자 0)

6.6 진단 결과를 근거로 참여 편익과 위약금 리스크를 제시한다.

- **연간 감축 가능량(kWh)은 DR 대상일 기준으로만 산출한다.**
- **정산 단가는 사용자 입력 필수, 기본값 없음.** 전력거래소가 매월 순편익가격
  (입찰 최소가격)을 공지하고 수요관리사업자 수수료가 별도이므로 우리가 만들 수 없다.
  단가가 없으면 감축량만 내고 금액은 "단가 미입력"으로 표시한다.
- 확실성 등급은 **'중간'**. 입찰 낙찰 여부와 참여일 수가 운영에 달렸다.
- **위약금 리스크를 반환에 포함한다** (별표26).

      실적위약금 = (감축계획량 − 실제감축량) × Max(하루전에너지가격, 0)

  투자비는 0원이지만 리스크가 0은 아니다.
- 필수 안내 문구:

  > 경제성DR은 수요관리사업자를 통해서만 참여할 수 있습니다.
  > 정산 단가, 계약 조건, 위약금 조항은 사업자와 상담하여 확인하십시오.

**기본요금 절감은 계산하지 않는다.** SMP 기준으로 산발적으로 입찰하므로 참여일이
연중 최대수요일일 확률이 낮다. 편익은 정산금 하나로 본다.

### 7.4 역률 개선 (저투자 — 콘덴서·APFR)

콘덴서 조정만으로 기본요금이 줄어든다. 근거는 5.7 절(약관 제41·42·43조)이다.

| 방향 | 내용 |
|---|---|
| 92% 미만 | 이미 나가고 있는 **추가요금을 없앤다.** 최대 기본요금의 6.4% |
| 92% 초과 | 97%까지 올려 **감액을 받는다.** 최대 기본요금의 1.0% |

- **확실성 등급은 '높음'** — 요금표와 약관만으로 확정되는 계산이다.
  발전량 예측 같은 불확실성이 없다. 감도(9.2)를 적용하지 않는다.
- 절감액은 재계산이다. 두 역률에서 각각 `calculate_bill()` 을 부른다.
- **97%를 넘겨도 요금은 더 줄지 않는다.** 넘기면 과투자이고, 야간에 진상으로
  넘어가 제43조 ②의 95% 조항에 걸릴 수 있다. 이 경고를 반드시 함께 낸다.
- 남는 불확실성은 역률 자체다. 청구서의 역률 항목을 넣으면 바로 재계산된다.

### 7.5 태양광

**발전량 산출**

- pvlib 기반, Open-Meteo 기상
- 다중 어레이 (지붕 + 벽면, 벽면은 경사각 90°)
- 어레이 상호 음영은 `pvlib.bifacial.infinite_sheds` 에 GCR 단일 파라미터 전달
- 기상 데이터는 `PROJECT_CACHE` 경로에 parquet 캐시

**기상 데이터 조회 순서**

Open-Meteo 는 호출 제한으로 실패할 때가 있다. 실패해도 검토가 멈추지 않도록
전국 3개년치를 미리 받아 둔다.

| 순서 | 경로 | 비고 |
|---|---|---|
| ① | `PROJECT_CACHE` 캐시 | **반복 호출을 여기서 막는다** |
| ② | Open-Meteo API | 성공분은 ①에 캐시한다 |
| ③ | 사전 취득분 `data\weather\` | **폴백 사실을 결과에 표시한다** |
| ④ | 없으면 **중단** | 0 으로 계산하거나 인접 격자로 대체하지 않는다 |

**사전 취득** (`tools\fetch_weather.py`)

- 지역 범위: 전국 / 시도 / 시군구. 기본 기간 2023-01-01 ~ 2025-12-31 (설정 가능)
- **0.25° 격자로 중복 제거** — 229개 시군구가 135개 셀이 된다 (서울 25개 구는 4셀)
- 호출 제한 대응: 호출 간 최소 간격(기본 1초, 설정 가능), 429·5xx 는 지수 백오프
  재시도, 재시도 후에도 실패한 셀은 **목록에 기록하고 계속 진행**, 종료 시
  성공/실패 요약과 실패 셀 목록 출력
- 이미 받은 셀·기간은 건너뛴다. **중단 후 같은 명령으로 재개된다**
- rich 로 진행 상황 표시

**저장 구조** (`data\weather\`)

- 격자 셀 × 연도 단위 parquet. 파일명에 격자 좌표와 연도

README 와 산출물에 싣는다.

**투자비 단가** — ESS 와 같은 규약으로 **용량 기준 단가** 하나를 받는다.

    투자비 = 설치 용량(kWp) × 입력단가(원/kWp)

- 총액 직접 입력 경로도 허용한다 (견적서를 받은 경우)
- **참고단가를 만들지 않는다.** ESS 는 에너지경제연구원 LCOS 연구라는 인용 가능한
  출처가 있지만 태양광은 확보하지 못했다. 근거 없는 기본값은 견적으로 둔갑한다.
  단가 미입력 시 **투자비 대신 사유를 반환한다** (0원이 아니다).
  공개 자료를 확보하면 채울 수 있도록 `PvCostReference` 자리만 열어 두었다
- **kWp 는 모듈 직류(DC) 정격**이며 인버터 용량(kW-ac)과 다르다. 입력 라벨에
  "DC 정격 기준"을 병기하고, 부대비용(옥상 가대·계통연계·인허가)의 포함 여부는
  입력한 견적 기준을 그대로 따른다 — 도구가 가정하지 않는다
- **규모의 경제는 반영하지 않는다.** 용량 곡선의 모든 점에 같은 단가를 적용하므로
  투자비가 용량에 선형이다. 실제로는 소규모일수록 kWp당 단가가 높아 작은 용량
  구간의 회수기간이 낙관적으로 나온다. 곡선 결과에 이 주석을 단다

**용량 곡선** — 0부터 옥상 가용면적 상한까지 20단계로 변화시키며 표시한다.

- 자가소비율
- 기본요금 절감액 / 전력량요금 절감액
- 잉여 발전량
- 단순 회수기간

"태양광을 얼마나 넣어야 하나"가 실제로 가장 많이 받는 질문이다.

### 7.6 ESS

**목표 피크 역산** — 사용자가 목표 요금적용전력을 조정하면 아래를 산출한다.

| 산출 항목 | 의미 |
|---|---|
| 초과 구간 수 / 총 시간 | 몇 번, 몇 시간 |
| **최대 초과 출력 (kW)** | 필요한 배터리 출력 |
| **하루 최대 초과 에너지 (kWh)** | 계통에 내보낼 에너지 (충전 기회가 야간뿐이다) |
| **정격 용량 (kWh)** | 필요한 배터리 용량 = 위 에너지 ÷ √왕복효율 ÷ DoD. **표시하는 것은 이쪽이다** (34세션) |
| **방전시간 (h)** | **산출값이다.** 정격 용량 ÷ 출력 (45세션) |
| 기본요금 절감액 | |
| 필요 ESS 사양과 개략 투자비 | 출력 × kW당 단가 |
| 단순 회수기간 | 현재 단가 기준 / 2030년 전망 단가 기준 |
| **손익분기 배터리 단가 (원/kW)** | 회수기간 10년이 되는 단가 역산 |
| **차익거래 잠재 수익** | 별도 줄. 절감액에 더하지 않는다 |

**출력(kW)과 에너지(kWh)를 분리해 보여주는 것이 핵심이다.** 목표를 조금만 낮추면
필요 에너지가 급감하는 경우가 많고, 그 사실이 배터리 사양을 완전히 바꾼다.

**디스패치** — 규칙기반 피크컷 단일 전략. 목표 초과분 방전, 경부하 시간대 충전.
MILP 최적화는 범위 밖이다.

#### 7.6.1 방전시간 — 산출값이다. 강제하지 않는다

    방전시간 = 정격 용량 ÷ 출력

목표 피크를 정하면 데이터에서 결정된다. **짧을수록 kW당 단가가 싸므로 경제성이
좋다** — 조달이 가능하다면 짧은 쪽이 맞다. 다만 0.5h 미만이면 경고를 표시한다.

**정격 기준이다** (45세션). 계통에 내보낼 에너지 기준으로 재면 DoD·왕복효율만큼
짧게 나오는데(샘플 0.82h 대 0.97h), 그 값을 쓰면 **사용자가 조달하는 사양과 다른
숫자를 내게 된다.** 34세션에 용량을 정격으로 고치면서 방전시간이 함께 옮겨지지
않아 한 카드 안에서 출력·용량·방전시간이 서로 맞지 않았다. 7.6.2 의
`kW당 단가 = CAPEX_Power + CAPEX_Energy × 방전시간` 도 정격 기준일 때만 맞는다 —
값을 치르는 대상이 정격 kWh 이기 때문이다.

> 산출 사양이 ○C 방전에 해당합니다. 정치형 LFP 는 통상 0.5~1C 연속이므로
> 고출력 셀 사양이며, 참고단가보다 비쌀 수 있습니다.

#### 7.6.2 참고단가 — 추정치가 아니라 **하한선**이다

출처: 에너지경제연구원 「효율적 탄소중립 실현을 위한 에너지저장장치비용(LCOS)
전망 및 최적믹스 수립 시스템 구축 연구」 (2025년 기준, 환율 1,412원/달러).
`data/ess_cost_reference.json` 에 출처와 함께 둔다. **하드코딩 금지.**

원본은 2성분(6시간 방전 기준)으로 저장하고 방전시간별 kW당 값으로 환산해 제공한다.

    kW당 단가 = CAPEX_Power + CAPEX_Energy × 방전시간

| 기술 | CAPEX_Power (원/kW) | CAPEX_Energy (원/kWh) | OPEX_Power (원/kW·년) |
|---|---|---|---|
| LFP 2025 | 245,295 | 369,936 | 10,770 |
| NCM 2025 | 245,295 | 475,633 | 12,139 |
| LFP 2030 | 213,225 | 284,175 | 9,108 |
| NCM 2030 | 213,225 | 391,064 | 10,313 |

양수발전(PSH)은 건물 대상이 아니므로 넣지 않는다.

환산 검산 (원/kW)

| 방전시간 | LFP 2025 | LFP 2030 |
|---|---|---|
| 0.5h | 430,263 | 355,312 |

UI 는 **산출된 방전시간에 해당하는 행을 강조한다** (8세션).
**참고값이 기본값으로 자동 적용되면 안 된다.** 명시적으로 골라야 한다.

**이 값의 성격** — 계통용 대형 ESS 기준이고, 전용실·소화설비 등 안전 규제
대응비와 수배전 연계공사비가 빠져 있다. **실제 견적은 반드시 이보다 높다.**
그래서 손익분기 배터리 단가와의 비교는 **비대칭**이다.

| 비교 | 판정 |
|---|---|
| 하한선 > 손익분기 | **경제성 없음** (강한 판정 — 더 싸질 여지가 없다) |
| 하한선 < 손익분기 | **견적 받아볼 가치 있음** (약한 판정 — 실제 견적이 넘을 수 있다) |

이 비대칭을 결과 문구에 그대로 담는다.

#### 7.6.3 차익거래

경부하 충전 → 최대부하 방전의 단가차익이다.

    수익/kWh·년 = Σ_계절 (최대부하단가 − 경부하단가 ÷ 왕복효율) × 계절별 평일수

**계시별 단가는 요금 엔진에서 자동으로 가져온다. 사용자 입력이 아니다.**
평일 수도 요금 달력에서 센다 — 최대부하가 실제로 존재하는 날만 세면 토요일
(중간부하까지)과 일요일·공휴일(전량 경부하)이 자동으로 빠진다. 평일 1사이클이
기본 가정이고 사이클 수는 설정으로 뺀다.

**차익거래 단독 회수기간도 함께 낸다.** 샘플 기준 연 19,476원/kWh 이므로
CAPEX_Energy 369,936원/kWh 대비 **19.0년**이다. 배터리 수명(10~15년)을 넘어
단독으로는 성립하지 않는다. **"왜 안 되는가"에 대한 답이 이 숫자다.**

차익거래 수익을 피크저감 절감액에 **더하지 않는다.** 도구가 돌리지 않는 운전의
잠재값이고, 그날 피크에 쓸 몫을 남기는 **예비 규칙이 없으면 피크를 못 깎아 오히려
나빠지며**, 사이클이 수십 배로 늘어나는 열화가 계산에 없다. 별도 줄로 표시하고,
회수기간은 두 기준(피크저감만 / 차익거래 포함 = 상한)을 함께 낸다.

#### 7.6.4 수익 구조 — 이것이 핵심 메시지다

    피크저감 수익  ∝ 출력(kW)    용량을 늘려도 늘지 않는다
    차익거래 수익  ∝ 용량(kWh)
    투자비         ∝ 용량(kWh)   (kW당 단가 = CAPEX_Power + CAPEX_Energy × 방전시간)

**따라서 용량을 늘릴수록 회수기간이 나빠진다.** 샘플 93.4 kW 기준.

| 방전시간 | 투자비 | 회수기간 (피크저감만) | 회수기간 (차익거래 포함) |
|---|---|---|---|
| 0.5h | 4,020만원 | 6.0년 | **5.3년** |
| 1h | 5,749만원 | 8.6년 | **6.9년** |
| 2h | 9,205만원 | 13.7년 | **9.2년** |
| 4h | 16,119만원 | 24.1년 | **12.2년** |

#### 7.6.5 2030년 전망 단가 기준 회수기간

    현재 단가 기준 ○년 / 2030년 전망 단가 기준 ○년

**"지금은 경제성 없음"을 "언제쯤 성립하는가"로 바꾼다.**

### 7.5-1 잉여 처리 — **7.5 태양광 안이다** (41세션)

**개선안 7.7 을 없앴다.** 잉여는 태양광을 얼마나 크게 지을지에 따라 나오는
**결과**이지 따로 고르는 수단이 아니다. 개선안은 여섯(7.1~7.6)이고 번호는 밀지
않는다.

**잉여가 0 이면 아무것도 보이지 않는다.** 태양광 카드의 「잉여 없는 최대 용량」 이
「생기려면 얼마가 필요한가」 에 답한다. 고를 것이 없는 자리에 선택지를 세우지 않는다.

```
잉여 처리 (접힘)
  남는 전기를 어떻게 하나   ( ) 상계거래(한전)  ( ) 외부 판매  ( ) 버리기
  ─────────────────────────────────
  연간 수익   약 ○○○만원/년
  근거        당월 차감 ○○○ kWh · 잔여 ○○○ kWh 를 SMP ○○원/kWh 로 정산
  날짜별 잉여 (막대)
```

**셋이고 기본값이 없다.** 27세션은 「버림」 이 언제나 0원인 줄이라 표에서 뺐으나,
41세션에 표가 아니라 **고르는 자리**가 되면서 뜻이 달라졌다 — 「아무것도 하지
않는다」 를 고를 수 없으면 셋 중 하나를 강요하게 된다. 상계와 외부 판매는 계약
상대도 정산 절차도 다르므로 **어느 쪽을 미리 골라 두면 그것이 권고로 읽힌다.**
이름은 **파는 곳**으로 적는다.

**상계거래.** 잉여가 난 슬롯의 **실제 계시**로 그 달 사용량에서 차감한다. 낮
시간을 일괄로 중간부하에 넣지 않는다 — 여름·봄가을 15~21시와 겨울 09~12시는
최대부하이고 태양광이 그 시간에도 발전한다. 요일 규칙은 요금 엔진 것을 그대로 쓴다.
그 달 그 계시 사용량을 넘으면 0 에서 멈추고 남은 몫을 **같은 계시로 다음 달에
이월**한다. 이월이 생긴 달만 표시하고 없으면 표시하지 않는다.

**설비 용량으로 구간을 가른다.** 판정은 설정된 kWp 로 한다 — 규정은 모듈 정격과
인버터 용량 중 작은 값이 기준이지만 초기 검토 도구이므로 인버터를 입력받지 않는다.

| 용량 | 처리 |
|---|---|
| 10 kW 이하 | 이월만 되고 현금 정산이 없다 |
| 10 kW 초과 ~ 1,000 kW | 당월 차감 뒤 기간 말 잔여를 SMP 로 정산 |
| 1,000 kW 초과 | 상계거래를 선택지에서 뺀다 |

**기본요금은 바뀌지 않는다.** 잉여는 부하가 낮은 시각에 나므로 요금적용전력과
무관하고, 태양광이 피크를 낮춘 효과는 이미 7.5 에 들어 있다. 전력량요금만 다시
계산한다.

**단가를 지어내지 않는다.** SMP 단가가 없으면 잔여 kWh 만 내고 금액은 「미산출」이다.
넣은 단가는 하나로 적용하며 기간 길이를 구분하지 않는다. 잉여 판매 단가도 같다.

**제도별 자격요건과 행정 절차는 별도 확인 필요**를 명시한다. 예상 행정 부담(계약 변경,
계량기, 정산 관리)을 한 줄로 병기한다. 자격 판정은 하지 않는다.

| + 태양광 ○○ kWp | ○○ | ○○ | ○년 | 중간 |
| + ESS ○○ kWh | ○○ | ○○ | ○년 | 중간 |

**확실성 등급은 산출물에 표시한다** (28세션 개정 — 그전에는 화면에도 두었다).

| 등급 | 대상 | 근거 |
|---|---|---|
| 높음 | 요금제 전환, 계약전력 조정 | 실측 데이터와 요금표만으로 확정 계산 |
| 중간 | 태양광 | 발전량 예측 오차 존재 |
| 중간~낮음 | ESS | 운전 전략과 열화에 좌우 |

**화면에서는 뺀다.** 무엇에 대한 등급인지가 이름에 없어 「높음」 이 어느 정도의
믿음인지 가늠할 수 없었고, 잉여가 0 이라 수익 0원이 확정인 줄에도 「중간~낮음」
이 붙었다. 등급이 보증도 아니며 이 도구는 초기 검토용이다 — 화면에서는 회수기간과
「미산출 — …」 사유가 그 자리를 대신한다. Excel 「수단별 결과」·「조합 비교」 와
Word 3장에는 그대로 싣는다.

**조합의 절감액은 단순 합이 아니다.** 태양광이 사용량을 줄이면 최적 선택요금이 바뀌고,
ESS가 피크를 낮추면 기본요금 기반이 달라진다. 조합마다 요금을 다시 계산한다.

## 9. 불확실성 처리

### 9.1 배경

태양광 발전량 예측은 **총량은 실측과 부합하나 피크 발전량이 과소 산출되는 경향**이 있다
(시간별 R² 약 0.8). 재분석·위성 일사 데이터의 공간·시간 평균화로 발전 프로파일이
평탄화되기 때문이다. 이 편향은 **피크 절감량을 과소 추정하는 방향**으로 작용하므로
결과가 이미 보수적이다.

R² 0.8 은 **시간당 값을 비교했을 때**의 값이고 기간 총량은 거의 같게 수렴한다.
어긋나는 곳은 시간대별 분포, 특히 피크 시간대다. **감도(9.2)를 이 성격에 맞춰
설계해야 한다** — 총량이 맞는데 총량을 흔드는 감도는 없는 불확실성을 만들어낸다.

### 9.2 감도 3종 — 첨예도 조정

확률 표기(P90 등)를 쓰지 않는다. 부하가 실측으로 고정되어 연도별 변동의 절반만
반영되므로 확률 표기는 통계적으로 정직하지 않다.

**계수를 PV 출력 전체에 곱하지 않는다.** 9.1 이 말하는 편향의 성격이 "총량 오차"가
아니라 **"프로파일 평탄화"** 이기 때문이다. 총량은 실측과 부합하는데(시간별 R² 약
0.8, 총량은 수렴) 일률 계수를 곱하면 총량을 ±30% 흔들게 되고, 그러면 전력량요금
절감액의 밴드가 과장되고 회수기간 밴드도 함께 부풀려진다. 편향이 평탄화이므로
감도도 **평탄화 정도**를 조정해야 한다.

    adjusted(t) = 일평균발전 + (기준(t) − 일평균발전) × s

평균을 축으로 진폭만 조정하므로 **일별 총 발전량이 보존된다.**

| 시나리오 | 내부 키 | 첨예도 s | 뜻 |
|---|---|---|---|
| **평탄형** | `conservative` | 0.85 | 정오가 낮고 어깨가 넓다 |
| **기준** | `base` | 1.00 | 시뮬레이션 그대로 |
| **첨예형** | `optimistic` | 1.25 | 정오가 높고 어깨가 좁다 |

**이 축은 낙관·비관이 아니다.** 총량이 보존되므로 첨예도를 올리면 정오가
높아지는 대신 아침·저녁 어깨가 낮아진다. 이름이 그 축을 가리켜야 오독이 없어서
표시 명칭을 평탄형/기준/첨예형으로 둔다. **내부 키는 그대로 두고 라벨만
분리한다** — 설정 파일과 케이스 정의가 키를 쓰고 있다.

**산출 규칙**

- 일평균발전은 **그날 발전이 있는 슬롯만의 평균**이고, 조정도 그 슬롯에만 건다.
  야간 0 을 평균에 넣으면 밤의 편차가 전체를 지배해 s 를 키웠는데 정오 출력이
  오히려 낮아지고, 야간 슬롯에 조정을 걸면 s < 1 일 때 **한밤중에 발전이 생긴다**
- 음수는 0 으로 클램프하고, 클램프 후 **일별 총량이 원본과 같도록 재정규화**한다
- `s = 1.0` 이면 원본을 그대로 돌려준다 — 기준 시나리오가 시뮬레이션 결과와
  완전히 같아야 회귀값이 흔들리지 않는다
- s 값은 `data\pv_presets.json` 의 `sensitivity_sharpness` 에서 읽는다. 하드코딩하지 않는다
- 실측 발전 데이터가 있으면 맑은 날 정오 구간의 **피크/일평균 비**의 예측 대비 실측
  비율에서 산출한다 (총량 비율이 아니다)
- 다년 기상 반복 계산 불필요

**이 방식이면 지표별 특수 처리가 필요 없다.**

| 지표 | 시나리오 간 차이 | 이유 |
|---|---|---|
| 발전량(kWh) | 없음 (±1% 이내) | 일별 총량 보존 |
| 전력량요금 절감액 | 거의 없음 (5% 이내) | 총량에 붙는다 |
| **기본요금 절감액** | **크게 벌어진다** | 피크 시각의 출력에 붙는다 |
| 요금적용전력 | 벌어진다 | 최대 15분 수요가 달라진다 |

기본요금 = 피크 저감이 kWise 가 재는 값이므로, **감도가 흔들어야 할 것만 정확히
흔든다.** 회귀 테스트로 고정한다 (11.2). 샘플(960 kWp)에서 발전량 편차 0.01%,
전력량요금 절감액 편차 0.16%, **기본요금 절감액 편차 11.3%** 였다.

**시나리오 이름은 발전 프로파일의 모양이지 절감액의 크기가 아니다.** 부하 피크가
정오에서 벗어나 있으면 '첨예형'의 기본요금 절감액이 오히려 작게 나온다 — 샘플은
최대수요가 09:30 인 오전 피크형이라 실제로 그렇게 나왔다 (평탄형 3,266만원 >
기준 3,152만원 > 첨예형 2,897만원). 일률 계수를 곱하던 이전 방식에서는
'낙관 = 절감액 최대'가 항상 성립했으므로 **읽는 방식이 바뀐다.** 산출물에 안내
문구(`SCENARIO_NAME_CAVEAT`)를 함께 싣는다.

**결과는 3열 나열이 아니라 범위로 표시한다.**

    기본요금 절감  3,152만원 (프로파일 감도 범위 2,897 ~ 3,266만원)

세 값을 나란히 놓으면 읽는 사람이 "어느 쪽이 좋은 값인가"를 찾게 되는데 이 축에는
좋고 나쁨이 없다. 최댓값·최솟값은 `min`/`max` 로 뽑고 **어느 시나리오가 상한인지
고정하지 않는다** — 건물 유형에 따라 평탄형에서 나올 수도 첨예형에서 나올 수도
있다. 원자료 3행 표는 근거로 남겨 별도 시트에 둔다 (10.3).

**요금제 전환·계약전력 조정·역률 개선에는 감도를 적용하지 않는다.** 실측 데이터와
요금표·약관만으로 확정되는 계산이다.

**감도는 산출물에만 싣는다** (28세션 개정 — 그전에는 3단계 화면에도 두었다).
계산은 그대로 돌고 Excel 「감도」·「감도 상세」 시트와 보고서가 받는다. 화면에서
뺀 이유 둘.

- **결론이 움직이지 않는다.** 흔들리는 것은 기본요금 절감액 한 줄(±15%)이고,
  총 절감액은 ±1.3%, 회수기간은 7.8→8.0년이다
- **목록에 감도와 무관한 절대 금액이 함께 실렸다.** 「기본요금 절감액」·
  「전력량요금 절감액」은 조합 전체(요금제 전환 포함)의 기준선 대비 값이라, 현행이
  선택Ⅰ이면 전력량요금 절감이 1억을 넘고 기본요금 절감은 음수가 된다. 그 감도
  폭은 0.03% 인데 읽는 사람은 그 억 단위 숫자를 다른 화면의 수단별 값과 견주게 된다

### 9.3 편차 보정 (옵션, 미구현)

분위수 사상(quantile mapping)으로 예측 분포를 실측 분포에 맞추는 기능.
총량을 보존하면서 상단을 복원한다. 실측 발전 데이터가 축적된 후 구현한다.

## 10. 출력과 UI

### 10.1 화면 구조 — 세 단계

**1단계 · 진단** — 업로드 즉시

입력은 계약 정보 넷뿐이다. 설비 정보는 묻지 않는다.

| 영역 | 내용 |
|---|---|
| 데이터 품질 | 기간, 결측률, 정전, 경고 |
| **개선 여지 요약** | 투자 없이 가능한 절감액 (6.5) |
| 부하 패턴 | 부하율, 기저부하, 주말 비율 |
| 피크 특성 | 월별 최대수요 차트, 상위 100구간 시각 분포 |
| 현재 요금 구조 | 기본요금 대 전력량요금, 시간대별 비중 |
| 계약전력 적정성 | 하한 판정과 목표 계약전력 |

**2단계 · 개선 수단** — 카드로 선택

수단마다 독립적으로 켜고 끈다. **투자비 순으로 배치한다.**

```
투자 0원   ─ 선택요금 전환
           ─ 계약전력 조정
투자       ─ 태양광 (잉여 처리를 접힘으로 안에 둔다)
           ─ ESS
```

각 카드는 접힌 상태로 시작하고, 펼치면 그 수단의 입력과 결과가 나온다.

**3단계 · 비교**

선택한 조합의 절감액·투자비·회수기간·확실성을 나란히 표시한다.

### 10.2 UI 원칙

- 핵심 KPI 만 기본 표시, 옵션 조정값은 확장 패널 안에 감춘다
- 차트는 altair 또는 plotly
- 계산 결과는 `st.cache_data` 로 캐싱
- 드롭다운 선택지는 요금 데이터 파일에서 생성
- 계산 로직은 순수 함수를 호출만 한다. UI 에 계산을 넣지 않는다
- 업로드 데이터를 서버에 영구 저장하지 않는다

### 10.3 Excel 상세

시트 구성: 요약 / 진단 / 월별 집계 / 15분 시계열 / 요금 계산 명세 / 수단별 결과 / 조합 비교 / 감도 / 감도 상세.

**감도 시트는 범위**(지표별 기준값·하한·상한)이고, 시나리오 3행 원자료는 `감도 상세` 에 둔다 (9.2). 태양광이 없는 케이스는 감도 시트에 사유만 적고 상세를 만들지 않는다.

**저장 직전 tz-aware 컬럼을 반드시 해제한다.**

```python
for col in df.columns:
    if isinstance(df[col].dtype, pd.DatetimeTZDtype):
        df[col] = df[col].dt.tz_localize(None)
```

파일명에 날짜·시각 접미사를 붙인다. 요약 시트 상단에 추적성 정보(5.8),
미포함 요금요소 안내(5.1), 계약전력 변경 경고(9.4), 알려진 한계(부록 D)를 넣는다.

### 10.4 CLI 배치

케이스 스터디용. YAML 케이스 정의 파일을 받아 여러 조건을 순차 실행하고,
케이스별 Excel 과 요약 CSV 한 장을 출력한다. 중간 결과를 저장해 재개 가능하게 만든다.

**원칙**

- **표는 Word 표 객체로 만든다. 이미지로 넣지 않는다.** 자사 제안서에 복사해

- **수단을 하나도 켜지 않아도 보고서가 나온다.** 진단만 보고 받아 가는 것이
  정상 경로다. 이때는 3·4장을 빼고 장 번호를 당기며, 무엇을 보지 않았는지는
  마지막 장의 「검토 범위」가 밝힌다.
- 한글 폰트를 명시한다 (`Malgun Gothic`). 본문은 동아시아 글꼴까지 지정해야
  Word 가 쓰고, matplotlib 은 지정하지 않으면 축 이름이 통째로 두부(□)가 된다.

### 10.6 진행 표시

오래 걸리는 구간에서 화면이 말없이 멈추면 사용자는 죽은 줄 안다. 실측상
**태양광 한 구간이 전체의 절반**이라 이 문제가 실제로 생긴다 (11.4).

**계산 모듈은 Streamlit 을 import 하지 않는다.** 화면은 콜백을 넘기고, CLI 는
같은 콜백에 rich 를 붙인다. 계산 쪽은 어느 쪽이 받는지 모른다.

```
ProgressReporter
    stage(name, total_steps)     단계 시작
    step(current, detail=None)   단계 내 진행
    done(name)                   단계 완료
    skipped(name, reason)        캐시 적중 등으로 건너뜀
```

콜백은 **선택 인자**다. 주지 않으면 아무 일도 하지 않는 보고자가 들어간다 —
콜백 없이 부르는 것이 여전히 정상 경로다.

| # | 단계 | 비고 |
|---|---|---|
| 1 | 데이터 읽기 | |
| 2 | 품질 검사 | |
| 3 | 진단 | |
| 4 | 기상 데이터 확보 | 캐시 적중이면 `skipped` |
| 5 | 태양광 발전량 | 용량 곡선 단계마다 `step` |
| 6 | 개선 수단 평가 | **켠 수단만** 세어 `total_steps` 를 잡는다 |
| 7 | 조합 비교 | 조합마다 `step` |
| 8 | 산출물 생성 | |

**화면 표시**

- `st.status` 로 단계별 상태를 접었다 펼 수 있게 한다
- `st.progress` 로 전체 진행률(%)
- 현재 단계와 세부를 한 줄로 — `5/8 태양광 발전량 — 용량 곡선 12/20`
- 건너뛴 단계는 사유와 함께 — `4/8 기상 데이터 확보 — 캐시 적중, 건너뜀`
- 오래 걸리는 단계는 **시작 전에** 예상 소요를 알린다

**진행률 가중치는 실측값이다.** 균등 분할하면 태양광 구간에서 막대가 멈춘 것처럼
보인다. 값은 `assumptions.json` 의 `progress.weights` 에 있고
`tools
un_benchmark.py` 가 만든다. 예상 소요는 `가중치 × progress.total_seconds` 다.

6단계의 수단 수는 `MEASURE_CATALOG` 를 세어 잡는다. **목록을 두 벌 두지 않는다.**

## 11. 검증

### 11.1 요금 엔진

가장 중요한 검증 대상이다. 우선순위대로 시도한다.

1. **실제 청구서 대조** — 확보 시 월별 기본요금·전력량요금을 ±1% 내로 재현
2. **자사 사옥·현장 사무소 청구서** — 종별이 달라도 계산 로직 검증에는 충분
3. **한전 공개 요금계산 서비스 대조** — 대표 케이스 몇 건
4. **수기 계산 단위테스트** — 요금표에서 직접 계산한 케이스 최소 5건

최소 4번은 반드시 구현한다. 1~3번 중 하나 확보를 인수 조건으로 한다.

**현황 (7세션)** — 수기 케이스 **7건**을 `tests/test_tariff_engine.py` 에 두었다.

### 11.3 케이스 스터디

실측이 1건뿐이므로 샘플을 변형해 합성 케이스를 만든다.

| 케이스 | 변형 | 종별 | 노리는 것 |
|---|---|---|---|
| C1 오전 피크형 | 원본 (10~13시 집중) | 일반용(을) | 기준 |
| C2 오후 피크형 | 프로파일 5시간 뒤로 | 일반용(을) | PV 최성기와 피크가 어긋난다 |
| C3 평탄부하형 | 부하율 85% (데이터센터) | 일반용(을) | 피크 저감 여지가 거의 없다 |
| C4 주말 가동형 | 주말을 평일의 90% (공장) | **산업용(을)** | 봄·가을 주말 할인 특례 |
| C5 겨울 피크형 | 여름↓, 겨울 07~09·17~20시↑ | 일반용(을) | 대상월인데 PV 가 닿지 않는다 |
| C6 야간 피크형 | 야간(22~08시) 최대 | 일반용(을) | **경부하는 요금적용전력 대상이 아니다** |

케이스 이름의 '평탄부하형'은 **부하**의 모양이고, 감도 시나리오의 '평탄형'은
**발전 프로파일**의 모양이다 (9.2). 서로 다른 축이므로 케이스 이름에
'평탄부하형'을 써서 구분한다.

생성 스크립트는 `tools/make_cases.py` 이고 산출물은 `input/cases/` 에 둔다.
**원본의 계절성·결측·그리드 이탈은 그대로 두고 시간대별 분포만 바꾼다.**
총량이 함께 흔들리면 전력량요금까지 움직여 어느 규칙이 작동했는지 알 수 없다.

**C5 의 겨울 피크 창을 07~09시·17~20시로 좁혔다.** 처음에는 07~12시로 잡았는데
10~12시에는 겨울에도 PV 가 발전해 피크를 깎아 버려서 "대상월인데 PV 가 약하다" 는
케이스의 뜻이 사라졌다. 실제 겨울 피크 건물도 새벽 난방 기동과 저녁에 걸린다.

#### 11.3.1 결과 타당성 자동 판정

물리적으로 성립해야 하는 관계를 테스트로 만든다 (`kwise.report.validity`).
**깨지면 계산 오류다.**

기본 (모든 케이스)

- PV 0 kWp 일 때 절감액이 정확히 0
- 용량 증가 시 전력량요금 절감액 단조 증가
- 기본요금 절감액은 단조 증가 후 포화
- 용량 증가 시 요금적용전력 단조 감소
- 확실성 등급이 최저 구성 요소를 따름

요금적용전력 3규칙 — **케이스마다 갈려야 한다**

잣대는 **요금적용전력 저감 폭(kW)과 저감률**이다. "기본요금 절감액 ÷ 기본요금"
으로 재면 안 된다 — 기본요금 자체가 요금적용전력에 비례하므로 피크가 낮은
케이스일수록 같은 kW 를 깎아도 비율이 커져 뜻이 뒤집힌다.

- C1 오전 피크형 > C2 오후 피크형 (저감 폭)
- C3 평탄부하형은 절감의 대부분이 전력량요금 (기본요금 비중이 C1 의 절반 미만)
- C5 겨울 피크형의 저감률이 C1 의 절반 미만
- C6 야간 피크형의 요금적용전력 < 관측 최대수요
- C6 야간 피크형의 저감률이 C1 보다 크다 (대상 슬롯이 주간뿐이다)
- C4 산업용(을) 주말 할인 시간대가 PV 최성기와 겹쳐 전력량요금 절감 비율이 낮다

감도 — **단조성을 요구하지 않는다**

- 세 시나리오의 일별 총 발전량이 ±1% 이내
- 기준값이 min~max 범위 안에 있음
- **평탄형 < 기준 < 첨예형 같은 순서를 요구하지 않는다.** 상한 시나리오가 건물
  유형과 용량에 따라 바뀐다. 케이스별로 어느 시나리오가 상한인지 표로 남긴다

감도와 무관해야 하는 것 — 확정 계산이다

- 선택요금 전환 / 계약전력 조정 / 역률 개선 절감액, 경제성DR 감축 가능량

#### 11.3.2 경계 케이스

- 12개월 미만 데이터 · 역년이 아닌 기간 · 1시간 간격 · 결측률 10%
- 계약전력 초과 구간 (요금적용전력과 **별개로** 검사)
- 기상 데이터가 없는 기간(2022년) + API 실패 → **중단하고 안내**

여기에 PV 용량 4단계 × 선택요금 전 조합 × 감도 3종을 겹친다.

**타당성 자동 판정** — 물리적으로 성립해야 하는 관계를 테스트로 만든다.

- PV 0 kWp 일 때 PV 절감액이 정확히 0
- PV 용량 증가 시 전력량요금 절감액 단조 증가
- 기본요금 절감액은 단조 증가 후 포화
- **C2 < C1** (기본요금 절감액) — PV 시간대와 피크가 어긋나므로
- C3 평탄부하형은 기본요금 절감이 거의 없음
- 감도 보수 < 기준 < 낙관
- 요금제 전환 절감액은 감도와 무관하게 일정

**경계 케이스** — 12개월 미만, 역년 아닌 기간, 1시간 간격, 결측률 10%,
계약전력 초과 구간 포함.

|---|---|
| 구간별 소요 | 어디가 느린가. **진행률 가중치의 근거다** (10.6) |
| RSS 증감과 최대 | 어느 구간이 메모리를 쥐는가. Streamlit Cloud 한도가 약 1 GB 다 |
| `calculate_bill` 호출 수 | **요금 재계산이 곱해지는 곳을 센다** |

세 번째가 핵심이다. 조합 × 감도 × 용량 단계가 곱해지면 호출 수가 급증하는데
시간만 봐서는 어느 축이 곱해졌는지 알 수 없다.

메모리는 Windows 작업 집합을 직접 읽는다. `tracemalloc` 은 파이썬 할당자만 보므로
**NumPy 배열이 빠지는데**, 이 도구에서 메모리를 쥐는 것이 바로 그 배열이다.
못 읽으면 `None` 이다 — **0 을 지어내지 않는다.**

**단위테스트로 고정할 것**

- 용량 곡선이 pvlib 시뮬레이션을 되풀이하지 않는다 (1회 계산 후 곱셈)
- 용량 곡선의 요금 재계산 횟수가 단계 수와 같다 (곱해지지 않는다)
- 조합 비교의 요금 재계산 횟수가 조합 수와 같다
- 성능을 고쳐도 회귀값(부록 B)이 한 자리도 바뀌지 않는다

## 12. 기준 데이터 관리

법령 유래 수치가 코드 상수로 흩어져 있으면 **사람이 볼 수도 고칠 수도 없다.**
근거와 확인일을 붙여 파일 하나로 모은다.

### 12.1 두 파일로 가른다

| 파일 | 무엇 | 근거 | 갱신 책임 |
|---|---|---|---|
| `data\rules_kr.json` | 법령·약관·규칙에서 온 값 | 조문 | 조문이 바뀌면 **반드시** 고친다 |
| `data\assumptions.json` | 우리가 정한 값 | `"판단값"` | 근거를 대면 바꿀 수 있다 |

**섞지 않는다.** 섞으면 "이 숫자를 우리가 정한 것인가 법이 정한 것인가" 를 되물을
수 없게 되는데, 그 물음이 갱신 판단의 전부다.

항목마다 아래를 둔다.

    value / label / source(조문) / source_date / verified_on / note

항목 키는 **점으로 구분한 평평한 키**다 (`power_factor.lagging_standard_pct`).
중첩 구조는 UI 표를 만들 때마다 펼쳐야 하고 편집 이력의 식별자가 흔들린다.
**키는 편집 이력과 항목별 원복이 걸린 식별자이므로 바꾸지 않는다.**

**코드에 기본값을 남기지 않는다.** 파일이 없으면 출고값에서 복사해 만들고,
그마저 없으면 명확히 실패한다. 기본값이 코드에 남아 있으면 파일을 고쳐도 반영되지
않는 사고가 나는데, **값이 그럴듯하기 때문에 결과를 다 쓰고 나서야 발견된다.**
같은 이유로 모듈 상수로 붙잡지 않고 **함수로 두어 부를 때마다 읽는다** — import
시점에 고정하면 UI 로 고쳐도 그 프로세스에서는 옛 값으로 계산된다.

계절·시간대·요일 규칙은 요금표 파일(`tariff_*.json`)에 이미 있으므로 **손으로
옮기지 않고 읽어 넣는다.** 두 벌이 되면 조용히 어긋난다 — 일치를 테스트가 지킨다.

### 12.2 편집 방식은 데이터 성격에 따라 나눈다

| 방식 | 대상 | 이유 |
|---|---|---|
| **엑셀 왕복** | 요금 단가, 시군구 좌표 | 항목이 많고 표 구조다 |
| **화면 편집** | `rules_kr.json`, `assumptions.json`, `ess_cost_reference.json` | 항목이 적고 **근거가 함께 보여야** 한다 |

기준 데이터에도 엑셀 왕복을 **보조 경로로** 둔다
(`tools\export_rules_xlsx.py` / `tools\build_rules.py`) — 여러 항목을 한꺼번에
훑거나 검토 의견을 주고받을 때 쓴다. 강제하지는 않는다.

**화면 편집의 동작**

- 값을 고치면 `verified_on` 을 오늘로 **자동 갱신**한다. 값을 고쳤다는 것은 원문을
  보고 고쳤다는 뜻이므로 확인일을 따로 누르게 하면 빠뜨린다
- 값은 그대로 두고 **"확인함"만 기록**하는 경로를 둔다. 없으면 만료 경고를 끄려고
  값을 무의미하게 고치게 된다
- 저장 전 **검증을 반드시 통과**시킨다. 실패하면 저장하지 않고 **어느 항목이 왜**
  틀렸는지 돌려준다
- 법령 유래 값과 판단값을 **구분해 반환**한다

검증 항목 — 역률 하한 < 기준 < 감액 상한, 진상 하한 < 진상 기준, 대상월이 1~12,
비율이 0~1, 임계값이 양수, 자원 유형 임계의 대소, 첨예도 평탄 ≤ 기준 ≤ 첨예,
교육용 임계 > 일반용 임계.

**편집 이력** — `data\rules_history.jsonl` 에 변경 일시·항목·이전 값·새 값을 한
줄씩 덧붙인다. **UI 로 고친 값은 git 에 남지 않으므로 이 파일이 유일한 추적
수단이다.**

### 12.3 원복 — 세 층

    data\defaults\    출고 기본값. 저장소에 커밋. **읽기 전용**
    data\             현재 값. 사용자가 편집
    data\backup\      편집 직전 자동 스냅샷. `.gitignore` 대상

실행 시 `data\` 에 파일이 없으면 `defaults` 에서 복사해 만든다.
**`defaults` 는 절대 덮어쓰지 않는다.**

| 원복 | 동작 |
|---|---|
| ① 직전 상태 | 가장 최근 백업으로. 백업은 **최근 10개**만 유지 |
| ② 출고 상태 | `defaults` 에서 통째로. **실행 전에 무엇이 달라지는지 항목별로 보여주고 확인받는다.** 복원 직전 상태도 백업에 남긴다 |
| ③ 항목별 | 한 항목만 출고값으로. **실무에서 가장 많이 쓰인다** |

기본값과 다른 항목을 판별하는 함수(`diff_from_defaults`)를 함께 둔다.

**같은 분에 두 번 저장해도 백업을 덮어쓰지 않는다.** 덮어쓰면 편집 직전 상태가
사라져 '직전으로 되돌리기' 가 방금 만든 상태를 되돌리게 된다.

**파일 손상 대응** — JSON 파싱에 실패하면 최근 백업 → 출고값 순으로 복구를
시도하고 **어느 쪽이든 사용자에게 반드시 알린다.** 손상된 파일은
`<이름>.json.damaged` 로 남긴다. 조용히 넘어가면 **갱신한 값으로 계산되는 줄 알고**
결과를 쓰게 된다.

### 12.4 만료 감지

`verified_on` 또는 근거 문서 시행일로부터 경과 기간을 재고 임계를 넘으면 경고한다.
확인일이 있으면 확인일을 축으로 잰다 — 그것이 "사람이 원문을 보고 아직 맞다고
판단한 날" 이다.

| 대상 | 임계 |
|---|---|
| 요금 단가 | 12개월 |
| 약관·규칙 | 24개월 |
| 참고단가·판단값 | 24개월 |
| 기상 | **전년도 미확보 시** |

임계값도 `assumptions.json` 에 있다 — 코드에 두면 "왜 12개월인가" 를 물을 곳이 없다.

**자동 수집은 하지 않는다.** 한전 요금표는 API 가 없고 연 1~2회 개정이라 수동
갱신이 현실적이다. 자동화하면 원문이 바뀐 것을 알아채지 못한 채 파싱만 실패하고
**그 실패는 조용하다.** 대신 경고와 함께 **원문 확인처**를 안내한다 (한전 요금표
페이지, 국가법령정보센터, 전력거래소, 에너지경제연구원).

갱신 절차는 README 에 적는다. **1년 뒤의 본인이 읽을 문서다.**

## 13. 문서

기술서와 매뉴얼을 **분리한다.** 독자와 갱신 주기가 다르다.

| | 독자 | 갱신 |
|---|---|---|
| `TECHNICAL.md` | 개발자와 1년 뒤의 본인 | **코드가 바뀔 때** |
| `MANUAL.md` | 사내 설계·영업 담당자 | **화면이 바뀔 때** |

**md 가 원본이고 html 은 생성물이다.** 두 벌을 손으로 유지하면 반드시 어긋난다.
`tools\build_docs.py` 로 변환한다. docx 는 만들지 않는다.

### 13.1 중복 방지

같은 내용을 두 문서에 쓰지 않는다. **한 곳을 정하고 나머지는 가리킨다.**

| 내용 | 어디에 | 다른 쪽은 |
|---|---|---|
| 계산식·산출 근거 | 기술서 4장 | "산출 근거는 기술서 4.2 참조" |
| 화면 사용법 | 매뉴얼 3~7장 | "실행 방법은 매뉴얼 2장 참조" |
| 근거 조문 | **기술서 부록 C 한 곳** | 양쪽이 가리킨다 |
| 알려진 한계 | 코드(`report.notices`) | 문서는 갈래만 적는다 |

### 13.2 HTML 요구사항

- **단일 파일.** 이미지는 base64 로 넣어 html 하나만 옮기면 되게 한다
- 목차 사이드바를 왼쪽에 고정하고 **현재 위치를 표시**한다. 좁은 화면에서는 접힌다
- 단계별 체크박스. **브라우저를 닫으면 사라진다는 것을 명시한다**
- 명령·경로에 복사 버튼
- 인쇄 스타일 — 사이드바를 숨기고 배경을 없앤다
- 웹폰트를 불러오지 않는다. 맑은 고딕까지 내려오는 글꼴 사슬을 둔다

### 13.3 앵커와 화면 링크

화면의 [자세히] 링크는 **8세션에서 확정한 32개 앵커**로 간다
(`docs\MANUAL_ANCHORS.md`). 매뉴얼이 그 id 를 그대로 쓰면 링크가 살아난다.

**Streamlit 은 임의 경로의 파일을 내주지 않는다.** `docs\MANUAL.html` 을 상대
링크로 걸면 404 가 된다. `build_docs.py` 가 `static\` 에 사본을 두고
`enableStaticServing` 을 켜며, 링크는 `app/static/MANUAL.html#<id>` 로 간다.

**빠진 앵커가 있으면 `build_docs.py` 가 종료 코드 1 로 멈춘다.** 죽은 링크를
화면에 내지 않는다.

### 13.4 화면 캡처

매뉴얼에 **자리와 캡션만** 잡아 두고 사람이 찍어 넣는다. 목록은
`docs\CAPTURES.md` 에 있다. 넣을 때는 base64 로 넣어야 단일 파일 규약이 지켜진다.

### A.2 검증 규칙 (단위테스트 필수)

단가를 수기로 옮길 때의 오타는 결과가 그럴듯하게 나와 발견하기 어렵다.
요금표 자체의 구조적 규칙을 테스트로 만들어 자동 검출한다.

**규칙 1 — 순서 관계**

- 모든 계절·전압·선택요금에서 `경부하 < 중간부하 < 최대부하`
- 기본요금: `선택Ⅰ < 선택Ⅱ < 선택Ⅲ`
- 전력량요금: `선택Ⅰ > 선택Ⅱ > 선택Ⅲ`
- `여름철 최대부하 > 봄·가을철 최대부하`

**규칙 2 — 선택요금 간 단가 차이 (적용 범위 한정)**

| 쌍 | 차이 | 균일성 검사 | 허용오차 |
|---|---|---|---|
| 고압A Ⅰ→Ⅱ | 5.5 원 | 적용 | ±0.05 |
| 고압B Ⅰ→Ⅱ | 3.8 원 | 적용 | ±0.05 |
| 고압B Ⅱ→Ⅲ | 1.6~1.7 원 | 적용 | **±0.15** (반올림 폭) |
| 고압A Ⅱ→Ⅲ | 0.6~12.4 원 | **미적용** | — |

**고압A Ⅱ→Ⅲ 는 할인이 최대부하에 집중된 구조다.** 경부하·중간부하는 0.6~1.3 원인데
최대부하는 8.3~12.4 원이다. 사용시간이 긴 고객을 겨냥한 의도적 설계이므로 균일하지 않은
것이 정상이다. 대신 아래를 검사한다.

- 최대부하 할인폭 > 중간부하 할인폭
- 최대부하 할인폭 > 경부하 할인폭

**규칙 3 — 손익분기 이용시간**

```
손익분기 이용시간(h/월) = 기본요금 차이 ÷ 전력량요금 차이
```

| 쌍 | 산출값 | 허용 범위 | 근거 |
|---|---|---|---|
| 고압A Ⅰ→Ⅱ | 1,100 ÷ 5.5 = 200 h | 150~250 | |
| 고압B Ⅰ→Ⅱ | 750 ÷ 3.8 = 197 h | 150~250 | |
| 고압B Ⅱ→Ⅲ | 810 ÷ 1.65 ≈ 491 h | 400~600 | 요금표 안내 "월 500시간 초과 고객에게 유리"와 일치 |
| 고압A Ⅱ→Ⅲ | 단일값 불성립 | — | 부하구성 의존 (전부 최대부하 120 h ~ 전부 경부하 1,656 h) |

**요금표의 선택요금 안내 문구와 산출값이 맞는지 대조하는 것이 가장 강력한 검증이다.**

**규칙 4 — 시간대 정의의 완전성**

- 각 계절의 경/중간/최대부하 구간 합이 정확히 24시간, 중복 없음

### A.3 드롭다운 생성

계약종별·전압구분·선택요금 선택지는 **하드코딩하지 않고 요금 데이터 파일에서 생성한다.**
데이터에 없는 조합은 선택지에 나타나지 않아야 한다.

### A.4 단계적 확장

PoC는 **일반용전력(을) 고압A·B만** 구현하고 검증한다. 통과 후 아래 순서로 확장하며,
확장 시에도 A.2 검증 규칙을 통과해야 한다.

1. 일반용전력(갑)Ⅰ·Ⅱ
2. 산업용전력(갑)·(을) — 주말 할인 특례 포함
3. 교육용전력(갑)·(을) — 임계값 1,000 kW 주의

## 부록 D. 알려진 한계

산출물과 README에 명시한다.

1. 기본요금과 전력량요금만 계산한다. 기타 요금요소는 미포함이며, 이들이 사용전력량에
   비례하므로 실제 절감액은 본 결과보다 크다.
2. 태양광 발전량 예측은 피크 발전량을 과소 산출하는 경향이 있다. 피크 절감량이 보수적으로 나온다.
   감도 3종(9.2)은 이 편향의 성격에 맞춰 **총량을 보존하고 첨예도만** 조정하므로,
   시나리오 밴드는 기본요금 쪽에서만 벌어진다.
3. 역률요금은 추정 역률 기반 산출이다. 무효전력 실측이 없다 — 약관 제42조는
   30분 누적 계량을 요구하는데 본 데이터는 15분 유효전력뿐이다. 기본값 92%는
   같은 조항의 무효전력계 미설치 간주값이며 그 값에서 추가·감액이 0원이다.
4. 역률 추가요금은 약관 제43조 ③에 따라 첫 달이 예고, 두 번째 달부터 청구다.
   기간에 따라 결과가 흔들리지 않도록 이 규칙은 계산에 넣지 않았으므로
   실제 첫 달 청구서와 어긋날 수 있다.
5. 결측 구간에 더 큰 수요가 있었을 수 있다.
6. 부하는 업로드한 데이터가 고정이다. 향후 운영 변화(공실률, 증설, 용도 변경)는 반영하지 않는다.
7. 인증·신고용 산출물이 아니다.
8. 상계거래·외부 신재생에너지 구매의 자격요건은 판정하지 않는다. 금액만 참고로 제시한다.
9. ESS 디스패치는 규칙기반 단일 전략이다. 최적 운전과는 차이가 있다.
10. 경제성DR 정산 단가는 산출하지 않는다. 전력거래소 월별 순편익가격과 수요관리사업자
    수수료에 따라 달라진다. 단가를 입력하지 않으면 감축 가능량(kWh)만 제시한다.
11. 경제성DR의 CBL(고객기준부하)은 전력거래소가 별표28 방식으로 산정한다
    (제12.5.2.1조). 본 도구의 감축 가능량은 실측 부하 기준의 추정이며 실제 정산
    기준량과 다르다.
12. **대한민국 전용 도구다.** 요금 체계(한전 기본공급약관·전기요금표), 역률 규정
    (제41~43조), 경제성DR(전력시장운영규칙 제12장), 공휴일, 시군구 좌표 229개가
    모두 한국 제도에 묶여 있다. 해외 부지에는 적용할 수 없다 (1.4).
13. 기상 자료는 Open-Meteo (ERA5 재분석)다. API 가 막히면 사전 취득분
    (`data\weather\`, 2023-01 ~ 2025-12)으로 계산하며 **그 사실을 결과에 표시한다.**
    둘 다 없으면 계산하지 않고 중단한다 — 인접 지역 기상으로 대체하지 않는다.
14. ESS 참고단가는 **하한선**이다 (7.6.2). 계통용 대형 ESS 기준이며 안전 규제
    대응비와 수배전 연계공사비가 빠져 있어 실제 견적은 반드시 이보다 높다.
    "경제성 없음" 판정은 강하고, "가능성 있음" 판정은 약하다.
15. ESS 차익거래 수익은 **매 평일 한 사이클을 온전히 돌렸을 때의 잠재값**이며
    피크저감 절감액에 합산하지 않았다. 그 운전을 하려면 그날 피크에 쓸 몫을 남기는
    예비 규칙이 필요한데 아직 정하지 않았고, 예비 없이 돌리면 피크를 못 깎아
    회수기간이 오히려 나빠진다. 사이클이 수십 배로 늘어나는 열화도 반영하지 않았다.
16. ESS 회수기간에 OPEX·열화·수명·교체비를 반영하지 않았다. 단순 회수기간이다.
17. 태양광 설치 단가의 참고값을 제공하지 않는다 (7.5). 인용할 공개 자료를 확보하지
    못했으므로 단가를 넣지 않으면 투자비와 회수기간을 산출하지 않는다.
18. 태양광 용량 곡선은 모든 점에 **같은 kWp당 단가**를 적용한다. **규모의 경제
    미반영**이며, 소규모 구간의 투자비가 과소·회수기간이 낙관적으로 나온다.

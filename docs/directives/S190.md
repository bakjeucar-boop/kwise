S190 — Word 마지막 장 못이 자리를 물게 고치고,
       화면 문구 후보를 한 자리에 모은다

1절은 고치는 절이고 2절은 모으는 절이다 — 2절은 한 글자도 안 고친다.
세션 도중 사람에게 묻지 않는다.

이 판의 못 박힌 안전한 쪽 일곱.
  · 계산을 안 고친다. 계산 다섯 폴더(tariff · measures · diagnose · pv ·
    compare)는 0줄이다.
  · 금액이 한 원이라도 움직이면 그 자리에서 멈추고 되돌린 뒤 값을 낸다.
    회귀값 여덟도 같다. 기대값을 갱신하지 않는다.
  · **산출물 글자를 안 고친다.** 1절이 고치는 것은 시험이지 Word 가
    아니다. 못이 무는 자리에 글이 없어서 빨간 것이면 고치지 말고 값을
    내고 이름으로 올린다.
  · 화면 문구를 안 건드린다. 2절은 모으기만 한다 — 고치거나 줄이거나
    자리를 옮기지 않는다. 감사 네 수가 갈리면 멈추고 값을 낸다.
  · 범위 밖에서 걸리는 것은 안 고치고 이름만 올린다.
  · 되돌려 확인은 src\ 를 고치지 말고 스크래치 monkeypatch · plugin 으로
    한다. 부득이 돌렸으면 git checkout HEAD -- 경로 로 되돌리고
    git status 를 본다.
  · 파일 수정도 재는 스크립트도 셸에 태우지 않는다. 스크래치 .py 로 만들어
    .venv\Scripts\python.exe 로 돌린다.

원인·전제를 미리 적지 않았다. 앞 판 보고의 수는 값이 아니라 다시 잴 것으로
다룬다 — 줄 번호와 이름은 지금 파일에서 다시 찾는다.


0절 — 판 열기

0-1  어느 PC 인지 먼저 확인한다. os.cpu_count() · RAM · -n auto 가 고른
     일꾼 수를 값으로 적는다. 이 판의 모든 소요에 PC 를 함께 적는다.
     1번 PC 면 pytest 를 통째로, 2번 PC 면 갈래 넷으로 나눠 돌린다.
0-2  git pull. HEAD 와 origin 이 같은지, 워크트리가 깨끗한지.
0-3  남의 python 을 센다. 세는 규칙은 CLAUDE.md 2항이 쥔다 — 그 잣대를
     따르고 **센 자리마다 값을 다 적는다.**

         Get-CimInstance Win32_Process -Filter "Name='python.exe'"

     0 이 아니면 소요에 「견주는 데 쓰지 않는다」 를 함께 적는다.
0-4  브리핑을 뜬다. 미해결 건수와 「다음 작업」 칸 글자 수.

         .venv\Scripts\python.exe tools\daily_brief.py

0-5  기상 캐시에 용인 벌이 있는지 본다. 없으면 케이스 스터디를 먼저 돌린다.
0-6  이 판이 건드릴 미해결의 지금 이름을 docs\OPEN_ITEMS.md 에서 그대로
     옮겨 적는다. 이름이 다르면 문서의 이름을 따른다.

커밋하지 않는다.


1절 — Word 마지막 장 못이 자리를 물게 한다

S189 가 값으로 봤다 — test_한계와_추적성이_마지막_장에_있다 는 추적성
목록을 빼면 빨갛지만 **주의 문단만 빼면 초록**이다. 같은 문단이 2장
(document.py:1652)에도 서기 때문이다. 못 이름은 「마지막 장에 있다」 인데
무는 것은 「어딘가에 있다」 다.

1-1  못이 지금 무는 것을 코드로 낸다 — 어느 글을 어느 범위에서 찾나.
     「마지막 장」 을 어떻게 잡는지, 잡지 않는다면 그 사실을 적는다.
1-2  그 못이 무는 두 가지(한계 · 추적성)가 Word 실물에서 각각 어느 장에
     서는지 전수로 낸다. 2장과 마지막 장 말고 또 서는 자리가 있는지 본다.
     **벌 하나가 아니라 종별이 갈리는 벌 둘 이상에서 본다** — 고른 벌
     이름을 적는다.
1-3  못을 고친다. **자리를 무는 꼴로 바꾼다** — 글이 마지막 장 안에
     있는지를 보게 한다. 시험만 고치고 src\ 는 안 고친다.
1-4  되돌려 확인한다. 셋을 다 본다.
       · 추적성 목록을 빼면 빨간가
       · **주의 문단만 빼면 빨간가**(이것이 이 판의 본체다)
       · 그 문단을 2장에만 두고 마지막 장에서 빼면 빨간가
     안 빨개지는 갈래가 있으면 그 사실과 까닭을 값으로 적는다.
1-5  같은 모양이 더 있는지 본다 — **「어느 장에 있다」 를 이름에 적고
     범위를 안 무는 못**이 tests\ 에 또 있는지 값으로 센다. 있으면
     고치지 말고 이름으로 올린다(범위 밖이다).
1-6  되돌림이 원복됐는지 git status · git diff 로 확인한다.

2절 — 화면 문구 후보를 한 자리에 모은다

고치지 않는다 · 줄이지 않는다 · 자리를 옮기지 않는다. 모으기만 한다.
문구는 사용자가 Streamlit 을 열어 한 판에 잡으므로, 이 절은 그 판이
설 수 있게 재료를 한 자리에 두는 것이 전부다.

2-1  docs\OPEN_ITEMS.md 에서 **화면 문구를 고쳐야 닫히는 항목**을 이름으로
     전수로 뽑는다. 갈래를 안 가린다 — 「나」 밖에도 있을 수 있다.
     번호가 아니라 이름으로 적는다.
2-2  그 밖에 기록에 흩어진 문구 후보를 더한다 — S189 가 미룬 화면 글자
     +27 자리(S10 계산 근거 표 · S11 선택요금 그림)를 포함한다.
     찾은 자리를 적는다.
2-3  후보마다 넷을 적는다 — 이름 · 어느 화면 자리(S번호) · 지금 글자 ·
     무엇이 걸려 있나(오독인가 · 이름이 틀렸나 · 길이인가).
     **고칠 안을 적지 않는다** — 사용자가 정한다.
2-4  후보마다 **screen_budget 예산 안인지 밖인지**를 값으로 적는다.
     접힘 · 툴팁 · 캡션은 예산 밖이다(S187 이 값으로 봤다).
2-5  후보 가운데 **화면 말고 다른 산출물에도 같은 글이 서는 것**을 이름으로
     낸다 — 화면만 고치면 어긋나는 자리다.
2-6  이 표를 docs\OPEN_ITEMS.md 가 아니라 **PROCEED.md 190세션 절**에 둔다.
     미해결 항목은 늘리지 않는다 — 이미 이름으로 서 있는 것들이다.

3절 — 회귀

3-1  git diff 로 계산 다섯 폴더가 0줄인지, src\ 가 0줄인지 확인한다.
3-2  pytest. 0-1 에서 잰 PC 에 따라 갈린다. 1번 PC 면 앞단에서 통째로.

3-3  소요를 적는다. PC · 일꾼 수 · 0-3 의 값 전부 · 깨끗한 판인지.
     **깨끗한 판이면 --durations=25 를 붙여 상위 스물다섯을 값으로 내고

5절 — 보고

마지막에 한 번만 보고한다. 중간 보고를 내지 않는다. 정확히 여덟 항목이고
그 밖의 서술을 덧붙이지 않는다. 표 칸은 30자 안쪽으로 쓴다.

  1 대조표 — 절·항마다 한 줄. 결과는 수치나 판정으로.
    0-3 칸에 센 자리마다 값을 다 적는다.
  2 만든/바꾼 파일 — 파일마다 +/− 줄 수. 계산 다섯 폴더와 src\ 가 0줄인
    것을 명시한다. 건드리지 않은 것도 한 줄.
  3 수치가 움직인 곳 — 종전/지금 표. 금액이 움직였으면 그 자리를 이름으로.
  4 판단한 것 — 스스로 고른 갈래와 그 근거. 특히 1-3 의 고친 꼴 ·
    1-2 의 고른 벌 · 2-1 의 뽑은 잣대.
  5 돌린 것 / 안 돌린 것 — 안 돌린 것은 까닭.
  6 예상과 달랐던 것 — 없으면 없음.
  7 프로젝트 지식 재업로드 — CLAUDE.md · collaboration.md ·
    project-overview.md 셋 중 이 판에 고친 것. 없으면 없음.
  8 박은 못 · 되돌려 확인한 못 — 이름으로. 못마다 「어디를 어떻게
    틀렸더니 빨개졌나」 한 줄. 확인 안 한 못은 「이번 판에 확인 안 함」 과
    「한 번도 확인 안 함」 을 갈라 적고 「어느 판 이전」 잣대로 센 수도 적는다.

ctx 칸을 셋으로 적는다 — 세션 예산 종전 → 지금(약 차이) · 가장 크게 먹은 것
하나 · 줄일 수 있었다고 보는 것 하나.

마지막 한 줄로 돌고 있는 백그라운드 셸이 없는지 확인한 결과를 적는다.

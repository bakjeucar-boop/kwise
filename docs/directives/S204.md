S204 — 값과 다른 말을 하는 글자를 한 판에 모으고, collaboration.md 두 자리를 고친다

**고치는 판이고 고치는 것은 화면·산출물 글자와 문서다. 계산은 0줄이다.**
S203 이 값으로 갈랐다 — 수단 카드와 조합의 두 수는 밑과 견주는 상대가
달라서 갈리고, **둘 다 정의에 맞는다.** 어느 쪽으로 맞추는 두 길도 배수를
1.0 으로 못 만든다. **그러므로 고칠 것은 값이 아니라 말이다.**
세션 도중 사람에게 묻지 않는다.

**이 판이 고치는 것은 「값과 다른 말을 하는 글자」 뿐이다**(결함 유형 ①).
표현이 어색하거나 길이가 마음에 안 드는 것은 **이 판이 안 고친다** —
자리와 조건만 값으로 세우고 사람이 화면을 열어 한 판에 잡는다.

이 판의 못 박힌 안전한 쪽 열둘.
  · **계산이 0줄이다.** tariff\ · diagnose\ · measures\ · pv\ · compare\ ·
    io\ 의 계산 줄을 안 고친다. **금액이 한 원이라도 움직이면 그 자리에서
    멈추고 되돌린 뒤 값을 낸다.** 회귀값 여덟 · 케이스 판정 174 도 같다.
  · **울타리는 자리 수다.** 이 판이 고치는 자리는 **1-4 가 「값과 다르다」 로
    센 자리와 6절의 문서뿐**이고, 그 밖에 한 자리라도 고쳐야 하면 멈추고
    값만 낸다. 넘으면 멈춘다.
  · **화면 문구를 늘리지 않는다.** 하나를 더하면 무엇을 뺄지 함께 정한다 —
    예산은 `tools\screen_budget.py` 가 쥔다. **새 안내를 붙이기 전에 이름을
    고쳐 해결되는지 먼저 본다.** 배경·근거·제도 설명은 매뉴얼로 보낸다.
  · **화면 감사 네 수가 늘면 늘린 까닭을 자리마다 적는다.** 줄면 어느 글자가
    줄었는지 적는다. **수만 적지 않는다.**
  · **「멈춘다」 가 서면 반드시 멈춘다.** 멈춘 자리와 안 멈춘 자리를 대조표에
    각각 한 줄로 적는다. 멈출 일이 없었으면 없었다고 적는다.
  · **원인을 미리 적지 않았다.** 앞 판 보고의 수(자리 36 · 글자 여덟 ·
    거짓 넷 · 조건별 벌 수)는 전부 **다시 잴 것**이다. 줄 번호와 이름은
    지금 파일에서 다시 찾는다.
  · **실물을 본다.** 소스 리터럴로 글자를 판정하지 않는다 — 화면은 png 를
    함께 보고(DOM 텍스트를 실물로 읽지 않는다), PPT·Excel·Word 는 떠서 본다.
  · 되돌려 확인은 스크래치 monkeypatch · plugin 으로 한다. **얕은 되돌림을
    조심한다** — 갈아 끼움이 어느 길에 닿고 어느 길에 안 닿는지 먼저 값으로
    낸다. src\ 를 더 돌렸으면 git checkout HEAD -- 경로 로 되돌린다.
  · **git stash 를 쓰지 않는다.** S140 스태시를 지우지 않는다.
  · **셸에 문자열을 태우지 않는다 — 다섯 판 연속 샜다.** 마지막 두 판은
    **값을 안 쓰는 군더더기**가 명령에 섞인 것이었다(뜻 없는 python -c ·
    Measure-Object | Out-Null). **쓰지 않는 조각을 명령에 붙이지 않는다.**
    python -c 를 한 번도 쓰지 않는다. 수를 세는 일에 PowerShell 파이프를
    쓰지 않는다. 재는 것 · 세는 것 · 한 줄 확인까지 전부 스크래치 .py 로
    만들어 .venv\Scripts\python.exe 로 돌린다. 커밋 메시지는 스크래치 .txt 에
    써서 git commit -F 로 단다. **남의 python 을 세는 Get-CimInstance 만
    예외다**(CLAUDE.md 2항) — 거기에 파이프를 덧붙이지 않는다.
  · **파일 수정은 편집 도구로 한다.** 문서를 고칠 때도 같다.
  · 백그라운드로 보내기 전에 예상 소요를 말한다. 근거는 S203 값이다 —
    덱 19벌 판이 각 약 4분 · 산출물 세 판 71.5초 · 케이스 한 판.
    상한을 걸고, 넘기면 스스로 멈추고 보고한다. 대기 루프를 만들지 않는다.
  · 앱을 띄우면 포트를 적고 내린 뒤 닫힌 것을 확인한다. 케이스 결과 xlsx 는
    저장소 판을 먼저 뜬 뒤에 돌린다.

표 칸은 30자 안쪽.

  1 대조표 — **절·항마다 한 줄이고 하나도 빠뜨리지 않는다.**
    0-3 칸에 센 자리마다 값을 다 적는다. **1-4 는 자리마다 ㄱ/ㄴ/ㄷ 로
    한 줄씩.** 1-5 가 센 울타리 수와 2절이 실제로 고친 자리 수를 나란히.
    **「멈춘다」 가 걸린 자리를 각각 한 줄로** — 멈춘 자리와 안 멈춘 자리를
    갈라서. 멈출 일이 없었으면 없었다고.
  2 만든/바꾼 파일 — **계산 폴더 여섯이 0줄인 것을 폴더마다 명시한다.**
    건드리지 않은 것도. **3-2 가 앉힌 파일 이름을 적는다.**
  3 수치가 움직인 곳 — **없어야 한다.** 움직였으면 멈춘 자리다.
    **화면 감사 네 수는 갈렸으면 자리마다 글자까지.**
  4 판단한 것 — 1-4 의 판정 근거 · 1-5 의 「이름이냐 글이냐」 · 2-3 에서
    뺀 것 · 6-3 이 훑어 본 상충. **권고는 적지 않는다.**
  5 돌린 것 / 안 돌린 것 — 안 돌린 것은 까닭. 백그라운드로 보낸 것이
    있으면 예상 소요를 미리 적었는지 함께. 앱을 띄웠으면 포트와 내린 것을 함께.
  6 예상과 달랐던 것 — 없으면 없음.
  7 프로젝트 지식 재업로드 — CLAUDE.md · collaboration.md ·
    project-overview.md 셋 중 이 세션에 고친 것. 셋 밖의 파일은 적지 않는다.

    됐는지 한 줄. 확인 안 한 못 수도.

S152 지시서 — 오늘 연 것을 저장소에 남긴다. 마무리 판

이 판은 기록 판이다. 계산·시험·도구를 안 고친다 —
src\ · tests\ · tools\ · data\ 를 한 줄도 안 바꾼다.
자료를 저장소에 앉히고, 값으로 확인하고, 기록에 남긴다.

까닭 — 오늘 웹 대화창이 산업용 실측 자료를 열어 값을 냈는데
저장소에는 한 줄도 없다. 남기지 않으면 다음 창에서 없는 일이 된다.
그리고 S151 이 낸 조사 결과 다섯이 아직 미해결에 이름으로 안 서 있다.

## 지킬 것

- 세션 중간에 묻지 않는다. 걸리면 안전한 쪽으로 진행하고 값을 보고에 낸다.
- 저장소가 정본이다. 이 지시서에 적힌 수도 이차 자료다 —
  웹 대화창이 잰 것이고 실물에서 다시 확인하라. 어긋나면 어긋남을 값으로 적는다.
- 답을 지어내지 마라. 못 짚으면 「못 짚었다」 와 무엇까지 봤는지를 적는다.
- 셸이 낸 수를 그대로 믿지 마라. 수는 두 방법으로 재서 같은지 본다.
  git 명령에는 core.quotepath 가 한글 이름을 이스케이프해 셈을 어긋나게 하는
  자리가 있다 (S148·S149·S150 세 판이 여기서 걸렸다).
- 파일 수정은 편집 도구로 한다. heredoc · echo · printf · sed/awk 치환 금지.
- PROCEED.md 에 grep 을 걸지 마라. daily_brief.open_items 로 이름을 떠 온다.
- 시험을 부를 때 -k 를 쓰지 마라. 노드 id 를 통째로 준다.
- 소요는 PC 를 함께 적는다.
- ruff format 어긋남 여덟과 맨 mypy 10건은 고치지 마라.
- 절마다 커밋한다. 보고는 마지막에 한 번만 한다.

## 1절 · 산업용 실측 자료를 저장소에 앉힌다

사용자가 `input\전력사용량_산업용(갑)저압.xlsx` 에 넣었다.

1-1. 파일이 그 자리에 있는지 값으로 본다. 크기와 수정 시각을 적는다.
1-2. 자료를 읽어 아래를 **직접 재서** 낸다. 아래 수는 웹 대화창이 잰 것이고
     이차 자료다 — 같은지 다른지를 값으로 적는다.

        행 수 11,712 = 122일 × 96 · 간격 15분 균일 · 중복 시각 0
        기간 2026-05-09 00:15 ~ 2026-09-08 00:00
        결측 6건(0.05%) · 정전 0
        관측 최대 52.88 kW @ 2026-08-11(화) 15:45
        평균 16.58 kW · 부하율 31.3% · 일평균 397.6 kWh
        주말 부하 비율 98.5%

1-3. 라벨 규약을 값으로 확인한다. 하루가 `00:15` 로 시작해 이튿날 `00:00` 으로
     끝나는지, `24:00` 표기가 몇 건인지 센다.
     kWise 로더가 이 파일을 그대로 읽는지 실제로 읽혀 본다 —
     열 이름 맞추기(`match_usage_column`)가 「사용량(kWh)」 을 잡는지 값으로 본다.
     못 잡으면 **고치지 말고** 무엇이 막았는지 적는다.
1-4. 검침월 넷으로 갈라 월별 값을 낸다. 경계는 09일 시작으로 잡는다.
     월마다 — 구간 수 · 사용량 · 15분 최대 kW · 1시간 평균 최대 kW.
     웹 대화창이 잰 것은 이렇다 (이차 자료) —
     05-09~06-08 29.22 · 06-09~07-08 33.55 · 07-09~08-08 **31.60** ·
     08-09~09-08 **52.88** kW.
1-5. 청구서 대조. 사용자가 준 8월 청구서 값은 셋이다 —
     계약종별 「산업용(갑)저압」 · 계약전력 75 kW · 최대수요전력 32 · 역률 100.
     **31.60 kW 를 1kW 단위로 올리면 32 인지** 약관 제7조 ①로 확인한다.
     넉 달 가운데 32 를 내는 창이 07-09~08-08 하나뿐인지 전수로 본다 —
     여러 창이 32 를 내면 그 사실을 적는다.
1-6. `docs\SOURCES.md` 나 시험 자료를 적는 자리가 있으면 이 자료를 등재한다.

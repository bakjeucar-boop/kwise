  결정 2 (PPT 조합 장 머리) — 머리 문장은 어느 입력에서도 한 문장이다: 「수단을 함께 도입하면 서로 영향을 주므로 조합을 통째로 다시 계산했습니다.」

  결정 5 (조합 표 누적 오독) — 조합 표는 줄마다 윗줄까지를 더한 누적값이다. 그래서 「+ 경제성DR 528만원」 이 경제성DR 한 수단의 몫으로 읽히고, 그림의
    「+ 경제성DR」 막대에는 투자비 8,000만원이 붙어 있다. 줄 구성은 그대로 둔다.
    (ㄱ) 두 번째 수단 줄부터 기간 절감액 칸을 「{누적} ({+그 줄 몫})」 으로 적는다 — 그 줄 몫 = 이 줄 적힌 값 − 윗줄 적힌 값(적힌 숫자끼리 맞는다).
    (ㄴ) 그림 캡션 「조합별 기간 절감액과 투자비」 → 「조합별 누적 기간 절감액과 누적 투자비」.
    PPT 조합 장만 고친다. 같은 원천을 쓰는 Word 자리가 함께 바뀌면 받아들이고 자리를 적는다. Excel 조합 비교는 그대로다.
  결정 6 (태양광 부록 역률 줄) — 「기간 역률요금 절감 | 기본요금이 줄면 함께 준다 | −4,000원」 의 산식 칸에 도입 후 역률을 적는다. 감액률이 그대로면
    「도입 후 역률 {x}% · 기본요금이 준 만큼 감액도 준다」, 감액률 · 추가율이 바뀌면 「도입 후 역률 {x}% · {전}% → {후}%」. 줄 이름과 값은 그대로다.
    1절에서 확인 사례 (가) 의 −4,000 이 「기본요금 절감 × 감액률 1.0% · 월별 천 원 처리」 로 풀리는지 값으로 먼저 잰다. 안 풀리면 고치지 않고 값을 낸다.

이 판의 못 박힌 안전한 쪽.
  · **기본 19벌과 확인 사례 셋은 금액 · 판정 칸이 한 자리도 안 움직인다.** 예외는 결정 8 의 끝 줄 표기 한 칸(확인 사례 (다) · 그 칸이 서는 벌)뿐이다.
    그 밖이 움직이면 멈춘다. 19벌에서 갈려도 되는 것은 1절 목록의 글자와 결정 3 으로 빠지는 장뿐이다 — 목록 밖이 갈리면 멈춘다.
  · **회귀값 여덟 가운데 하나라도 움직이면 기대값을 고치지 않고 멈춘다** — 이름 · 전 → 후를 값으로. 케이스 스터디 타당성 판정이 갈려도 멈춘다.
  · 새 글자는 결정 1 ~ 3 · 5 · 6 에 적힌 글자 밖으로 짓지 않는다. 옮긴 ※ 가 장에서 넘치면 글자를 줄이지 않는다 — 넘친 장과 벌을 값으로 내고 사람이 정할
    것으로 올린다.
  · **계산 폴더 여섯(tariff · measures · diagnose · compare · pv · quality)은 1-6 이 센 자리 밖 0줄.**
  · 화면 문구(글자)는 늘리지 않는다. CLAUDE.md 「화면 문구」 절이 걸리면 그대로 따른다.
  · 옛 표기를 문 시험이 빨개지면 시험을 고친다(전 · 후). 회귀값 여덟을 문 시험은 고치지 않는다.
  · **CLAUDE.md 0줄 · tools\ 0줄.** 소요 · 깨끗한 판 · 전원 · 남의 python 을 재거나 적지 않는다.
  · 이력 · 결정 주인은 저장소에서 찾는다 — 없으면 「기록 없음」. 이미 기록된 결정을 다른 자리에 다시 적지 않는다 — 가리키기만 한다.
  · **센 값만 적는다. 벽시계는 시각을 찍는 셸 명령의 출력을 보고 그 값만 옮긴다. 커밋 메시지는 편집 도구로 지은 .txt 로 git commit -F.** 절마다 따로
    커밋한다. 1절 기록을 커밋한 뒤에 2절 코드를 짓는다.
  · 세션 도중 사람에게 묻지 않는다.
  · **pytest 는 지시서에 적힌 명령 꼴만 쓴다 — 3-1 꼴 · 3-3 되돌림 꼴 · 3-8 꼴 · 아래 디버그 꼴 · 4-7 꼴. 그 밖에 `-n` · `--dist` · `--tb` · `-s` 를 붙이지
    않는다.** python 은 늘 `.venv\Scripts\python.exe` 로 부른다.
    빨간 시험 하나의 까닭을 볼 때만 아래 디버그 꼴을 쓴다 — 판 수에 넣되 초록 판정에 쓰지 않는다. node id 는 수집 목록에서 복사해 옮긴다. 한글 인자 id
    가 셸을 못 넘으면 그 시험 파일을 `-k` 없이 3-1 꼴로 돌려 까닭 줄을 본다.

         .venv\Scripts\python.exe -m pytest <빨간 시험 하나의 node id> -rf --tb=short

  · **메모리 부족으로 끊기면** — 덱 19벌은 곧바로 다시 돌지 않는다. 이미 스냅이 선 벌은 두고 남은 벌만 같은 도구 · 같은 옵션으로 나눠 뜬다. 전체
    pytest 는 처음부터 한 파일씩이다(3-8). 한 파일 판도 끊기면 멈춘다. 끊긴 판은 판 수에 넣고 까닭 한 줄. 멈추면 3절까지 커밋하고(push 하지 않는다)
    끊긴 자리를 보고한다.
  · git stash(list 도) · heredoc · python -c · Set-Content · Out-File · sed 로 파일 고치기 · 셸 리다이렉트(> · >> · `> $null`)를 쓰지 않는다 — 파일
    수정은 편집 도구로만 한다.
    **파이프를 쓰지 않는다 — `| Out-Null` · `| ForEach-Object` · `| Select-Object` · `| Sort-Object` · `| Measure-Object` 도 파이프다.** 명령 출력이
    길면 그대로 받아 읽고, 파일은 찾기 도구나 읽기 도구로 본다.
    python 을 foreach 로 여러 번 부르지 않는다 — 여러 벌은 도구 하나에 인자로 넘긴다(S257 이 5.4MB 출력을 냈다). 조사 에이전트를 띄우면 이 금지를 글자
    그대로 전한다.

S193 — 산출물 지문이 입력을 물게 하고, 어제 어긋남 셋이 옛 파일에서
       왔는지 값으로 가른다

고치는 판이고 **고치는 것은 하나다** — 내려받기 자리의 지문이 입력을
안 물어 입력을 갈아도 옛 파일을 낸다(S192 가 값으로 봤다 · compare.py:1126).
세션 도중 사람에게 묻지 않는다.

이 판의 못 박힌 안전한 쪽 여덟.
  · **고칠 자리가 지문(캐시 열쇠) 하나를 넘으면 멈추고 값만 낸다.**
    넘겨야 닫히는 것이 보여도 고치지 말고 이름으로 올린다.
  · 계산을 안 고친다 — tariff\ · measures\ · diagnose\ · pv\ · compare\ 의
    **계산 코드**는 0줄이다. 고치는 것은 산출물을 내는 자리뿐이다.
  · 금액이 한 원이라도 움직이면 그 자리에서 멈추고 되돌린 뒤 값을 낸다.
    회귀값 여덟도 같다. 기대값을 갱신하지 않는다.
  · 화면 문구를 안 건드린다. 감사 네 수가 갈리면 멈추고 값을 낸다.
  · **3절이 내는 판정을 4절이 고치지 않는다** — 어제 셋이 진짜 결함으로
    갈려도 이 판에서 안 고친다. 이름으로 올리고 사람이 다음 판에 정한다.
  · 되돌려 확인은 src\ 를 고치지 말고 스크래치 monkeypatch · plugin 으로
    한다. 부득이 돌렸으면 git checkout HEAD -- 경로 로 되돌리고 git status 를 본다.
  · **앱을 띄운 채 끝내지 않는다** — S191 이 띄운 앱이 S192 소요 셋을
    오염시켰다. 띄웠으면 내리고 포트가 닫혔는지 본다.
  · 파일 수정도 재는 스크립트도 셸에 태우지 않는다. 스크래치 .py 로 만들어
    .venv\Scripts\python.exe 로 돌린다.

원인·전제를 미리 적지 않았다. 앞 판 보고의 수는 다시 잴 것이다 —
줄 번호와 이름은 지금 파일에서 다시 찾는다.

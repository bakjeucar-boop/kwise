S188 — 기간 값을 적는 자리에 이름을 단다 (길 ㄴ)

이 판은 고치는 판이다. 값을 한 원도 안 바꾼다 — 글자만 고친다.
세션 도중 사람에게 묻지 않는다.

사람이 정한 것 넷 (다시 묻지 않는다).
  · 정본은 길 ㄴ 다 — 기간 값을 그대로 쓰고 그 자리에 이름을 단다.
  · 이름은 「기간」 한 낱말이다. 날짜 범위를 붙이지 않는다.
  · 이 판이 다는 것은 S187 1-2 의 「이름도 짝도 없는 기간 자리 23」 뿐이다.
    12개월 쪽 이름 없는 자리 셋(M2 PPT 수단 장 · M4 덱 안 장 사이 ·
    M5 화면 2단계 카드)은 안 건드린다 — 미해결에 이름만 올린다.
  · PPT 잉여 장 머리 「연 수익」 은 값이 기간이므로 이름을 기간으로 간다.
    이것은 길과 무관하게 이름과 값이 어긋난 자리다.

이 판의 못 박힌 안전한 쪽 일곱.
  · 계산을 안 고친다 — tariff\ · measures\ · diagnose\ · pv\ · compare\ 는
    0줄이다. 고치는 것은 report\ 와 ui\ 의 글자뿐이다.
  · 금액이 한 원이라도 움직이면 그 자리에서 멈추고 되돌린 뒤 값을 낸다.
    회귀값 여덟도 같다. 기대값을 갱신하지 않는다.
  · 화면 자리(S10 계산 근거 표 · S11 선택요금 그림)에서 느는 글자가
    27자를 넘으면 멈추고 값을 낸다. 안 고치고 보고한다.
  · 자리가 S187 표와 다르면 지금 파일을 따른다. 앞 판 표는 값이 아니라
    다시 잴 것이다.
  · 범위 밖에서 걸리는 것은 안 고치고 이름만 올린다.
  · 되돌려 확인은 src\ 를 고치지 말고 스크래치 monkeypatch · plugin 으로
    한다. 부득이 돌렸으면 git checkout HEAD -- 경로 로 되돌리고
    git status 를 본다.
  · 파일 수정도 재는 스크립트도 셸에 태우지 않는다. 스크래치 .py 로 만들어
    .venv\Scripts\python.exe 로 돌린다.

원인·전제를 미리 적지 않았다. 줄 번호와 이름은 지금 파일에서 다시 찾는다.


0절 — 판 열기

0-1  어느 PC 인지 먼저 확인한다. os.cpu_count() · RAM · -n auto 가 고른
     일꾼 수를 값으로 적는다. 이 판의 모든 소요에 PC 를 함께 적는다.
     1번 PC 면 pytest 를 통째로, 2번 PC 면 갈래 넷으로 나눠 돌린다.
0-2  git pull. HEAD 와 origin 이 같은지, 워크트리가 깨끗한지.
0-3  남의 python 을 센다. 세는 횟수가 PC 마다 다르다 — 사람이 정했다.

         Get-CimInstance Win32_Process -Filter "Name='python.exe'"

     1번 PC 는 세 번이다 — 판 앞 · 회귀 앞 · 회귀 뒤. 앞단에서 통째로
     돌리는 동안에는 중간을 잴 수 없고 대기 루프는 금지이므로 중간을
     안 센다. 2번 PC 는 네 번이다 — 갈래 사이를 함께 센다.
     「깨끗한 판」 은 그 PC 의 세는 자리가 다 0 인 판이다.
     0 이 아니면 소요에 「견주는 데 쓰지 않는다」 를 함께 적는다.
0-4  브리핑을 뜬다. 미해결 건수와 「다음 작업」 칸 글자 수.

         .venv\Scripts\python.exe tools\daily_brief.py

0-5  기상 캐시에 용인 벌이 있는지 본다. 없으면 케이스 스터디를 먼저 돌린다.
0-6  이 판이 건드릴 미해결의 지금 이름을 docs\OPEN_ITEMS.md 에서 그대로
     옮겨 적는다. 이름이 다르면 문서의 이름을 따른다.

3절 — 이름을 무는 못을 박는다

3-1  이름이 선 것을 무는 못을 박는다. 못이 무는 것은 글자이지 식이 아니다.
     덱 벌 18 전부에서 서야 한다 — 배율 1 인 열일곱에서도 이름이 붙는

     한 줄로 남긴다. 소스만 보는 꼴이면 ②-59 가 쥔 한계를 그 자리에 적는다.
3-3  못을 되돌려 확인한다 — 이름을 옛 글자로 갈면 어디서 빨개지는지
     한 줄로. 안 빨개지면 그 사실과 까닭을 적고 고치지 않는다.
3-4  되돌림이 원복됐는지 git status · git diff 로 확인한다.

재는 판이다. **고치는 판이 아니다** — 잣대가 어긋난 것이 보여도 이 판에서
안 고친다. 값으로 내고 사람이 다음 판에 정한다.
세션 도중 사람에게 묻지 않는다.

이 판이 재는 것은 뿌리 하나다 — 「절감이 0 이거나 여지가 없는 수단을 거르는
잣대가 자리마다 달라 조합 이름과 문장에 선다」. S192 가 증상 넷(7·8·9·10)을

(덱 small-a2-pf100-offset-area · 케이스 R4)을 세웠다.

이 판의 못 박힌 안전한 쪽 열하나.
  · **src\ 가 0줄이다.** 계산도 화면도 안 고친다. 이 판이 건드리는 것은
    tests\ 와 기록뿐이다. 고쳐야 닫히는 것이 보여도 이름으로 올린다.
  · **잣대를 하나로 모으지 않는다.** 정본을 이 판에서 정하지 않는다 —
    자리마다 무엇이 다른지만 값으로 낸다.
  · 금액이 한 원이라도 움직이면 그 자리에서 멈추고 되돌린 뒤 값을 낸다.
    회귀값 여덟 · 케이스 판정 174 · 감사 네 수도 같다. 기대값을 갱신하지
    않는다 — 새 값은 xfail 못으로 남긴다.
  · **이 판이 박는 못은 「지금 어긋나 있다」 를 무는 못이다.** 고쳐지는 날
    스스로 빨개지는 꼴로 박는다(59세션이 열아홉 판을 서 있다 78세션에
    알린 그 꼴이다). 지금 사실을 못이 무는 것이지 옳은 값을 무는 것이 아니다.
  · **못이 소스 글자나 식을 다시 적으면 안 된다** — 실물에 뜬 값을 본다.
    S194 가 소스 글자를 보는 못 하나를 이름으로 올렸고, 그것이 결함 유형 ⑤ 다.
  · 되돌려 확인은 src\ 를 고치지 말고 스크래치 monkeypatch · plugin 으로
    한다. 부득이 돌렸으면 git checkout HEAD -- 경로 로 되돌리고
    git status 를 본다.
  · **셸에 문자열을 태우지 않는다. 두 판 연속 샜다** — S194 스크래치
    무한 루프 · S195 python - << 'EOF' 의 SyntaxWarning. 병은 heredoc 이
    아니라 문자열을 셸에 한 겹 더 태우는 것이다. 파일 수정도, 재는
    스크립트도, 한 줄짜리 확인도 **전부** 스크래치 .py 로 만들어
    .venv\Scripts\python.exe 로 돌린다. 셸에는 파일 이름만 싣는다.
  · **스크래치는 %TEMP% 라 저장소 밖이다.** 저장소를 찾아 올라가는 고리를
    쓰지 않는다. 경로는 인자로 받거나 절대경로로 적는다.
  · 백그라운드로 보내기 전에 예상 소요를 말한다. 모르면 모른다고 적는다.
    상한을 걸고, 넘기면 스스로 멈추고 보고한다. 대기 루프를 만들지 않는다.
  · 앱을 띄운 채 끝내지 않는다. 띄웠으면 내리고 포트가 닫혔는지 본다.
  · 케이스 스터디 결과 파일이 날짜만 붙어 같은 날 두 판이 덮인다
    (S195 6항). 이 판이 남기는 판을 덮기 전에 저장소 판을 먼저 뜬다.

# 우리가 일하는 방식

이 문서는 **웹 대화창과 클로드코드가 어떻게 나눠 일하는가**와,
지금까지 세션이 쌓아 올린 **판단 원칙**·**반복해서 나온 결함 유형**을 적는다.

**코딩 규약은 여기 없다.** `CLAUDE.md` 에 있다 — 가상환경·경로·인코딩·
캐시 위치·백그라운드 실행 10항·화면 문구 절·금지 목록. 중복해서 적지 않는다.
충돌하면 **`CLAUDE.md` 가 이긴다.**

---

## 1. 역할 분담

| | 웹 대화창 (판단하는 쪽) | 클로드코드 (짓는 쪽) |
|---|---|---|
| 무엇 | **무엇을 왜 고칠지 정한다** | **어떻게 고칠지 정하고 짓는다** |
| 한다 | 세션 지시서 · 절 나누기 · 우선순위 · 산출물 검토 · 용어 결정 | 코드 · 시험 · 측정 · 문서 · `PROCEED.md` 기록 · 커밋·푸시 |
| 안 한다 | 코드를 직접 쓰지 않는다 | 범위를 스스로 넓히지 않는다 |
| 근거 | 실물(화면·PPT·Excel)을 열어 본 것 | 돌려서 나온 수치 |

**지시서 번호가 세션 번호의 정본이다.** 저장소가 두 번 밀렸고(24~25, 56~57)
그때마다 지시서에 맞췄다. 55세션 자리는 비워 두었다 — 번호를 지어내지 않는다.

**작업 PC 는 두 대**, GitHub 를 사이에 두고 번갈아 쓴다.
시작 전 `git pull`, 종료 시 `git push`. 안 올리면 그 PC 에만 남는다.

## 2. 판단 원칙

### 화면에 관한 것 — `CLAUDE.md` 「화면 문구」 절이 정본이다

셋만 여기 다시 적는다. **늘리지 않는다** · **새 안내를 붙이기 전에 이름을 고쳐
해결되는지 먼저 본다**(설명이 필요하다는 건 대개 이름이 틀렸다는 뜻이다) ·
**배경·근거·제도 설명은 매뉴얼로 보낸다.** 나머지(예산, `screen_audit.py`
전후 실행)는 `CLAUDE.md` 를 본다.

49세션이 이 원칙의 순수한 사례다 — 「최적」 을 「최단 회수기간」 으로
**이름만 고쳤고 계산과 회귀값은 한 줄도 안 바뀌었다.**

### 계산에 관한 것

**2단계 카드는 독립 평가다.** 수단끼리 영향을 주고받지 않는다.
합성은 3단계에서만 하고, 거기서는 **수단마다 요금을 처음부터 다시 계산한다.**
절감액을 더하지 않는다.

**근거 없이 값을 만들지 않는다.** 모르는 것은 모른다고 화면에 낸다.
자료를 기다리는 미해결 여덟이 전부 이 상태로 처리되어 있어서, 금액을 지어내지
않고도 화면과 보고서를 그대로 쓸 수 있다. 자료가 들어오면 값만 바꿔 낀다.
**결측은 보간하지 않는다** — 계산에서 빼고 그 사실을 적는다.

**판단값과 법령 유래를 가른다.** 기준 데이터가 두 파일로 갈라져 있다.

    data\rules_kr.json      31항목   source = 「기본공급약관 제57조」 같은 조문
                                     source_date · verified_on 이 붙는다
    data\assumptions.json   49항목   source = 「판단값」
                                     화면에서 [판단] 으로 보이고 고칠 수 있다

**코드에 기본값을 두지 않는다.** 값을 못 찾으면 실패한다 — 조용히 폴백하면
어느 값을 썼는지 아무도 모른다(21세션에 폴백을 걷어냈다).
`data\defaults\` 는 출고 복원용 사본이라 **현재 항목과 개수가 같아야 한다**
(56세션에 11건이 빠져 있었고, 그 상태로 출고 복원을 누르면 항목이 사라졌다).

**전제가 사라진 결정은 명시적으로 뒤집는다.** 14세션의 「잉여는 합산에 넣지
않는다」 는 잉여가 독립 개선안이던 시절의 결정이었다. 41세션에 태양광 안으로
들어간 뒤에도 그 결정이 남아 **241만원이 누락되고 있었다**(48세션).

### 세션 운영

**절마다 커밋한다.** 세션 하나를 절로 쪼개고 절이 끝날 때마다 커밋한다
(`S59 15절: 대조표 …`). 중간에 끊겨도 어디까지 됐는지 남는다.

**진행표는 지우면서 간다.** 미해결 목록은 **해결된 것을 지운다** — 경위는
세션 기록에 있으니 목록에 남기지 않는다. 남은 것만 보이게 한다.

**대조표로 닫는다.** 지시서가 항목 N개를 주면 마지막 절에서 **N개를 하나씩
대조한 표**를 만들고, 그 표가 다 차야 세션이 끝난다. 53세션 스물여섯,
59세션 열다섯이 그렇게 닫혔다. 대조표 없이 「다 했다」 고 하지 않는다.

**끝내면 `PROCEED.md` 에 적고 커밋·푸시한다** (`CLAUDE.md` 「세션 종료 시」).

## 3. 반복해서 나온 결함 유형 다섯

**같은 모양이 여러 번 나왔다.** 고칠 곳을 찾을 때 이 다섯을 먼저 뒤진다.

### ① 화면이 사실과 다른 말을 한다

계산은 맞는데 화면 문구가 옛 사실을 가리키고 있다.
34세션 — 값을 고쳤는데 **근거 문구가 안 따라왔다.**
59세션 — 태양광 절감액 큰 글자가 **역률 영향 반영 뒤 실제로 남는 돈과 달랐다.**
**고칠 때 「이 사실을 화면에서 누가 또 말하고 있나」 를 센다.**

### ② 만든 갈래가 실물에 한 번도 안 섰다

경고·분기·장치를 만들어 놓고 **그것이 뜨는 조건이 실제로 존재하는지** 안 봤다.
46세션 — 가장자리 경고의 창이 곡선 전체를 덮어 **차집합이 늘 공집합이었다.**
구조적으로 죽어 있었다 — 안 뜬 게 아니라 **뜰 수가 없었다.**
59세션 — **갑 종별에서 ESS 장이 통째로 빠지고 있었다.**
**장치를 만들 때 「이것이 뜰 수 있는 조건」 을 함께 시험한다.**
**뜨지 않는 경고는 없는 경고와 같다.**

### ③ 같은 말이 다른 사실을 가리킨다

한 이름이 두 자리에서 다른 것을 뜻한다.
9세션 — 상수를 옮기면서 **의미가 갈라졌다.**
51세션 — **표식 어휘가 각주와 어긋났다** (`measures/base.py` 한 곳으로 모았다).
52세션 — 「48」 과 「40」 이 같은 자리에서 다른 것을 뜻하고 있었다.
28세션 — 3단계 「연간 절감액」 열에서 **상계 수익 한 칸만 기간 기준이었다.**
**어휘는 한 곳에만 둔다. 옮길 때는 「무엇 옆에 두는가」 가 아니라 「성격이 같은가」 를 본다.**

### ④ 캐시 열쇠에 조건이 빠져 앞 결과가 남는다

59세션 곁가지 — **캐시 열쇠에 계약종별이 없어 갑이 을 결과를 쓰고 있었다.**
57세션은 반대 방향이다 — 잉여 수익을 열쇠에서 **빼서** 시나리오를 바꿔도
요금이 다시 안 돌게 했다 (6.5초 → 0.9초).
**결과를 가르는 조건은 전부 열쇠에 있어야 하고, 결과를 안 가르는 것은 없어야 한다.**

### ⑤ 시험은 통과하는데 실물은 깨져 있다

**이 프로젝트에서 가장 비쌌던 유형이다.**
54세션 — **ESS 절감액이 전 구간 음수**였는데 시험은 다 통과했다.
케이스 스터디가 **ESS 를 아예 안 돌리고 있었다.**
48세션 — 배경 실행이 `exit code 0` 인데 `test_integration.py` 6건이 깨져 있었다.
38세션 — 사용자가 PPT 를 **처음 열어 보고** 나서야 구조 문제가 나왔다.

**실물을 여는 절차를 코드로 만들어 두었다.**

    tools\render_deck.py --case large-a --png    실제 화면을 띄워 PPT 를 뽑고 png 로 편다
    tools\run_casestudy.py                        타당성 90/90 · 45초
    tools\screen_audit.py                         실주행 문구를 모아 규칙 위반을 센다
    tools\run_benchmark.py                        단계별 소요 (예상 시간의 근거)

**종료 코드로 통과를 판정하지 않는다** — 출력에서 실패 줄을 직접 본다
(`CLAUDE.md` 백그라운드 8항).

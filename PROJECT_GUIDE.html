01

사전 준비

클로드코드를 켜기 전에 사람이 직접 하는 일. 폴더를 만들고 문서를 배치한 다음, 그 폴더에서 클로드코드를 실행한다. 1세션 프롬프트는 프로젝트 폴더를 새로 만들라는 뜻이 아니라, 이미 만들어 둔 폴더 안에 pyproject.toml 과 src\kwise\ 모듈 뼈대를 만들라는 뜻이다.

도구 설치 (한 번만)

# PowerShell 에서 실행 (관리자 권한 불필요) > winget install --id Git.Git -e > winget install --id Python.Python.3.12 -e > # Claude Code 네이티브 설치 (WSL 불필요) > irm https://claude.ai/install.ps1 | iex # 새 PowerShell 창을 열고 확인 > claude doctor
Git for Windows 는 선택이 아니라 사실상 필수입니다. 클로드코드가 Git Bash 를 내부 셸로 사용합니다. 없으면 PowerShell 로 대체되지만 일부 기능이 제한됩니다. claude 명령을 못 찾으면 %USERPROFILE%\.local\bin 을 PATH 에 추가하고 터미널을 다시 여세요.

프로젝트 폴더

> mkdir C:\work\kwise > cd C:\work\kwise # 내려받은 파일 묶음을 이 폴더에 풀어 넣는다 # setup.ps1 이 폴더 생성 · git init · .venv 까지 처리한다 > .\setup.ps1

setup.ps1 이 하는 일은 도구 확인, 폴더 생성, .gitignore· .gitattributes 작성, git init, .venv 생성, 환경변수 설정이다. 수동으로 하려면 아래를 순서대로 실행한다.

> mkdir docs, input, output, data, reference, src\kwise, tests > git init > py -3.12 -m venv .venv > .venv\Scripts\activate
활성화가 거부되면 실행 정책을 한 번만 완화합니다. Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

환경변수 — 영구 등록

Windows 의 Python 기본 인코딩은 cp949 다. 설정하지 않으면 한글이 깨진다.

> notepad $PROFILE # 파일에 아래 두 줄을 추가하고 저장, 터미널 재시작 $env:PYTHONUTF8 = "1" $env:PROJECT_CACHE = "$env:LOCALAPPDATA\kwise\cache"

.gitignore

setup.ps1 이 아래 내용으로 작성한다.

output/ __pycache__/ *.egg-info/ build/ dist/ .venv/ venv/ cache/ *.lock.txt .pytest_cache/ .ruff_cache/ .mypy_cache/

input/ 은 제외하지 않는다. 케이스 스터디용 데이터를 이력으로 남겨야 검증 결과를 재현할 수 있다. 다만 저장소를 외부에 공개할 때는 발주처 데이터 포함 여부를 다시 확인한다.

클로드코드 실행

# 문서와 참조 코드를 모두 배치한 뒤 > cd C:\work\kwise > .venv\Scripts\activate > claude # 세션이 열리면 05장의 프롬프트를 붙여 넣는다
순서는 이렇게 됩니다. 도구 설치 → 폴더 생성 → 문서·참조 코드 배치 → setup.ps1 실행 → claude 실행 → 1세션 프롬프트 붙여 넣기. 프롬프트가 폴더를 다시 만들지 않습니다. 이미 있는 폴더 안에서 패키지 뼈대만 세웁니다.

S3요금 엔진핵심

시작 전 — PROCEED.md 의 요금 단가 원본 대조를 먼저 끝낼 것. 여기가 틀리면 전부 틀린다

프롬프트
PROCEED.md 를 읽고 3세션을 시작한다. kwise/tariff 모듈을 구현한다.
요구사항서 5장과 부록 A 를 따른다. 이 세션이 가장 중요하다.

1. 요금 데이터
   - 부록 A.1 스키마의 JSON 을 data/tariff_kr_20260601.json 으로 작성
   - PoC 범위는 일반용전력(을) 고압A·B 만. 다른 종별은 넣지 않는다.

2. 요금 데이터 검증 (부록 A.2) — 단위테스트로 구현
   - 순서 관계: 경부하 < 중간부하 < 최대부하
   - 기본요금은 선택I < II < III, 전력량요금은 반대 방향
   - 선택요금 간 전력량요금 차이가 9개 셀 전부 동일한지
     (고압A 5.5원, 고압B 3.8원)
   - 손익분기 이용시간이 100~400 h/월 범위인지
   - 각 계절 시간대 구간 합이 정확히 24시간인지
   이 규칙들이 수기 입력 오타를 잡는 유일한 수단이다. 빠짐없이 구현한다.

3. 시간대 분류기
   - 계절 판정, 시간대(경/중간/최대) 판정
   - holidays 라이브러리로 공휴일 판정
   - 토요일: 최대부하 → 중간부하 계량
   - 공휴일: 전부 경부하 계량
   - 임시공휴일 추가·제외를 인자로 받는다

4. 요금 계산기 — 순수 함수로 작성한다. streamlit 을 import 하지 않는다.
   - 월별 최대수요 (15분 기준)
   - 요금적용전력: 당월 + 직전 11개월 최대값
   - 기본요금, 전력량요금
   - 반환: 월별 명세 DataFrame + 연간 합계

5. 선택요금 비교
   - 주어진 종별·전압의 모든 선택요금으로 계산
   - 최저 요금 조합 판정
   - 선택지 목록은 JSON 에서 생성한다. 하드코딩 금지 (부록 A.3)

6. 단위테스트 — 요구사항서 10.2 의 항목을 모두 구현한다.
   계절·시간대 경계값(5/31 23시, 6/1 0시, 겨울 12시 경계)과
   요금적용전력 12개월 규칙을 꼼꼼히 테스트할 것.
   수기 계산 케이스를 최소 5개 만들어 넣는다.

   - C3 평탄형      : 부하율 85% (데이터센터 성격)
   - C4 주말 가동형 : 주말 부하를 평일의 90% (공장 성격)
